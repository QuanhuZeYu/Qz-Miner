# Review: issue234 单人退出世界闪退

## 范围

- GitHub issue `#234`
- 客户端断线与世界卸载时的预览清理逻辑

## 主要发现

- issue 结论成立，属于真实缺陷，不是误报。
- `ClientConnectionListener.onClientDisconnected(...)` 直接调用 `cleanupPreviewResources(...)`，而该事件从报错栈可见运行在 `Netty Client IO` 线程，不是持有 OpenGL 上下文的客户端主线程。
- `cleanupPreviewResources(...)` 进一步调用 `ChainPreviewRenderer.disposeForLifecycle()`，最终进入 `ChainPreviewMeshCache.dispose()` 执行 `GL30.glBindVertexArray(...)`、`GL30.glDeleteVertexArrays(...)`、`GL15.glDeleteBuffers(...)` 等 OpenGL 释放操作；这与 issue 中的 native crash 栈完全一致。
- 当前统一清理入口没有先收口到客户端主线程，意味着后续只要有其他异步线程复用该入口，仍会复现同类问题。

## 关键代码位置

- `src/main/java/club/heiqi/qz_miner/client/ClientConnectionListener.java:50-80`
- `src/main/java/club/heiqi/qz_miner/chain/client/ChainPreviewRenderer.java:41-45`
- `src/main/java/club/heiqi/qz_miner/chain/client/ChainPreviewMeshCache.java:149-169`
- 现有主线程调度参考：`src/main/java/club/heiqi/qz_miner/ClientProxy.java:55-67`

## 审查结论

- 根因不是 GPU 资源不该清理，而是清理线程错误。
- 修复点应放在 `ClientConnectionListener` 的统一清理入口，将生命周期清理调度到 Minecraft 客户端主线程后再执行；在 1.7.10 环境下可直接复用 `Minecraft.getMinecraft().func_152344_a(...)` 这一现有调度方式。
- `WorldEvent.Unload` 路径即便后续与断线路径发生重复清理，当前 `stopPreview()` 和 `dispose()` 逻辑本身具备幂等性，重复执行不是主要风险，错误线程才是触发崩溃的决定性原因。

## 后续动作

- 已完成：`ClientConnectionListener.cleanupPreviewResources(...)` 已改为通过 `ClientMainThreadDispatcher` 收口到客户端主线程执行。
- 将 `cleanupPreviewResources(...)` 本身改为线程收口点，而不是只在单个 `dispose()` 调用外层临时补调度。
- 修复后优先回归验证：单人进入世界 -> 触发任意预览/连锁 -> 退出世界，不应再出现 `No context is current`。
