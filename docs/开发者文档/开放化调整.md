# 开放化调整

本文件记录从内部实现到对外入口的开放边界。

## 当前状态

- 自动工具换位的 Qz-Miner 协议 v4 五包（round/intent/result/phase）是内部客户端/服务端原子版本边界，不是公共 API。`5.2` 及更旧端在 5.3 版本校验处 fail-closed；外部接入方不应依赖包 ID、字段布局、round 状态或 `actionSequence` 细节。
- 普通 `CHAIN/AREA` 的新 production 热路不通过自动工具 wire 请求逐目标候选：`AutoToolSwapServerBatchService` 在服务端主线程独占 local session/physical ledger，逐目标读取实时库存并执行二槽交换、三槽轮转和恢复；`AutoToolSwapRoundService` 只是零库存 projection/control facade。外部接入方不得把 RoundService、client reducer、coordinator 或 packet callback 当作第二库存写入口。
- local mutation 与原版 publication 分离：mutation 正常返回即提交，异常只按 pre/post/unknown image 分类且不重放；一个 batch 可多次 mutation，但每玩家/tick完整 window 0 publication 最多一次，terminal 先 restore 再发布。`MinecraftAutoToolSwapInventoryPort` 的交换/轮转与 full window 0 publication 是内部实现边界，不是第三方事务 API；客户端不得自行写库存或通过容器点击模拟。
- client 激活 round 后 direct `FREEZE`；`AutoToolSwapTakeoverRequest`、客户端库存扫描、target rematch 和 coordinator 已删除，不提供跨 minor fallback 或 source compatibility 壳。
- `client.autoToolSwapEnabled` 与 `client.autoToolPrioritySelectors` 的 schema 路径保持不变；local owner 读取服务器自己的 `CommittedSnapshot`，活动 session 冻结 policy，远程客户端值不能写服务器 Authority。
- planner 的 confirmed/preview 按顶层模式表达不同边界：CHAIN 是 PlanStarted 冻结“主手 + 背包全部工具 + 空手”能力后的连通拓扑，matcher=false 即断链；AREA 是空间与子模式结构范围内的待尝试目标，不按工具过滤。扩展 matcher 必须复用同一顶层 mode evaluator，worker 不得读取实时库存或当前主手。真实破坏资格与 `tryHarvestBlock` 结果仍由服务端主线程逐目标终裁。
- 未声明 Forge harvestTool 的工具兼容入口是 Minecraft 稳定 `Item.canHarvestBlock(Block, ItemStack)`；这不是新的 Qz-Miner 公共适配 API，也不承诺模组类白名单。候选与 CHAIN 冻结能力的硬门为 canHarvest 与耐久储备；效率只是可选事实，采样异常仅降级为 false。
- `club.heiqi.qz_miner.objectgroup` 下的 selector/parser/domain/snapshot 是 Qz-Miner 配置与运行时内部模型，不是稳定扩展 API。metadata 当前使用完整非负 int domain；旧 `metadataMask/fromMask` 只是 16-bit 内部实现并已删除，不提供反向兼容壳。外部接入只应依赖 `registry@meta` canonical 字符串、现有 LIST<STRING> schema 与已声明的 wire 上限，不依赖内部 Java 方法或容器类型。
- 自动工具 target numeric 字段只存在于服务端本地候选模型，不通过 5.3 wire 暴露。五包 v4 control wire、动作码、字段顺序与固定 framing 仍是 5.3 内部兼容边界，外部不得依赖 packet ID、字段布局与 round 细节。

## 适合写入本文件的内容

- 对外配置入口开放范围。
- 兼容开关暴露策略。
- 内部实现迁出为公开接口的边界。
- 外部接入方依赖的稳定约束。
