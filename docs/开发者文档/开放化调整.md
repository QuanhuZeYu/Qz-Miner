# 开放化调整

本文件记录从内部实现到对外入口的开放边界。

## 当前状态

- 自动工具换位的 Qz-Miner 协议 v4（round/intent/result/phase/takeover target）是内部客户端/服务端原子版本边界，不是可混版本调用的公共 API。v3 及更旧端在版本校验处 fail-closed；外部接入方不应依赖包 ID、字段布局、round 状态、普通 `actionSequence` 或独立 `takeoverRequestId` 细节。
- 自动工具协议只承载换位请求、结算、连锁阶段关联和服务端目标请求，不替代原版库存同步。中途接替保持同一 `serverRoundId`；客户端在下一 ClientTick 选候选，服务端重验后执行双槽交换或单次三槽引用轮转。mutation 与 publication 分离：写入只提交一次，后续 exact retry 只重发完整原版 window 0 与同一 ActionResult。客户端不应自行写库存或通过原版容器点击模拟该事务。
- planner 的 confirmed/preview 按顶层模式表达不同边界：CHAIN 是 PlanStarted 冻结“主手 + 背包全部工具 + 空手”能力后的连通拓扑，matcher=false 即断链；AREA 是空间与子模式结构范围内的待尝试目标，不按工具过滤。扩展 matcher 必须复用同一顶层 mode evaluator，worker 不得读取实时库存或当前主手。真实破坏资格与 `tryHarvestBlock` 结果仍由服务端主线程逐目标终裁。
- 未声明 Forge harvestTool 的工具兼容入口是 Minecraft 稳定 `Item.canHarvestBlock(Block, ItemStack)`；这不是新的 Qz-Miner 公共适配 API，也不承诺模组类白名单。候选与 CHAIN 冻结能力的硬门为 canHarvest 与耐久储备；效率只是可选事实，采样异常仅降级为 false。
- `club.heiqi.qz_miner.objectgroup` 下的 selector/parser/domain/snapshot 是 Qz-Miner 配置与运行时内部模型，不是稳定扩展 API。metadata 当前使用完整非负 int domain；旧 `metadataMask/fromMask` 只是 16-bit 内部实现并已删除，不提供反向兼容壳。外部接入只应依赖 `registry@meta` canonical 字符串、现有 LIST<STRING> schema 与已声明的 wire 上限，不依赖内部 Java 方法或容器类型。
- 自动工具 target 的两个 numeric 字段保持 signed `int` wire：存在目标 block ID 为正 int、metadata 为非负 int，block ID 0 是缺席 sentinel。v4 只重新解释既有 long 关联字段并保留六包、动作码、字段顺序与固定 framing；完整值域与请求号语义都不构成公共 API 开放，外部仍不得依赖 packet ID、字段布局与 round 细节。

## 适合写入本文件的内容

- 对外配置入口开放范围。
- 兼容开关暴露策略。
- 内部实现迁出为公开接口的边界。
- 外部接入方依赖的稳定约束。

## 维护规则

- 只记录长期有效边界。
- 临时试验不沉淀。
