# 门禁脚本说明

> 本目录下为文档纪律自动传感器。
>
> 控制论角色：**传感层自动传感器**。把结构/纪律约束从「人工评审逐条核对」
> 拉回「脚本一键闭环」，让违规在合并前被机械捕获，不依赖评审纪律单独守卫。
>
> 代码结构边界门禁（守 import 层面的架构边界）暂未建立：Qz-Miner 的关键约束多为
> 行为约束（线程主权/协作式取消/反射安全），grep import 难以机械守护。后续若识别出
> 可 grep 的 import 边界（如某包禁 import 客户端类），再扩 `check-code-boundaries.ps1`。

## 脚本清单

| 脚本 | 守护对象 | 控制论角色 |
|---|---|---|
| `scripts/check-doc-discipline.ps1` | 文档纪律（防流水账/历史文档堆积） | 文档纪律传感器 |
| `scripts/check-doc-fact-drift.ps1` | 文档事实一致性（防现状锚引用已删类） | 事实漂移传感器 |
| `scripts/check-agent-environment-ownership.ps1` | agent 环境只读所有权与绕过禁令 | 环境所有权传感器 |

环境所有权门禁扫描现行 `AGENTS.md`、`PERSISTENT-WORKFLOW.md`、`TASK-BRIEF.md`、稳定命令、Python agent 入口与既有 PowerShell 实现；CI workflow 和历史 errors 排除。它阻断常见环境写入、持久化、敏感回显、全量枚举及 Gradle home/JDK override，并组合断言默认 build 的 ACTIVE 任务授权、Gradle v1 Python 入口和 `shell=False` 锚。对直接 PowerShell/wrapper 或双基线授权只做已知文本模式诊断，不构成完整安全证明。运行 `python scripts/run-agent-command.py repo-script check-agent-environment-ownership --self-test` 验证 fixtures。

## 文档纪律门禁（check-doc-discipline.ps1）

> 解决 vibe coding 常见的"记流水账、留历史文档堆积"反模式。

### 断言清单

| # | 断言内容 | 权威源 |
|---|---------|--------|
| 1 | **决策目录禁日期编号文件名**：不得出现 `DECISION-YYYYMMDD-*` 或 `DECISION-` 前缀 | `docs/反馈层/决策/README.md`（按主题归并原则） |
| 2 | **交接简表行数 ≤ 15**：`交接.md` 表格数据行不超上限，防单调增长 | `docs/反馈层/交接.md` 维护说明（覆盖不堆历史） |
| 3 | **错误预防禁时态标题**：不应有日期/年份/序数标题，只留通则 | `docs/反馈层/错误预防.md`（只留通则） |
| 4 | **持久任务可提交且不依赖旧载体**：`INDEX.md` 必须存在，任务文件不得被忽略或引用旧 task/handoff | `PERSISTENT-WORKFLOW.md` + `TASK-BRIEF.md` |
| 5 | **docs 禁会话流水账文件名**：不应有"第N次""YYYYMMDD"编号文件（决策目录交断言1；`ERROR-*.md` 由 AGENTS.md 4.3 允许；`REVIEW-*.md` 由 4.5 允许） | `AGENTS.md` 4.1 文档协作 |

### 运行命令

```text
python scripts/run-agent-command.py repo-script check-doc-discipline
```

- 通过：输出 `文档纪律门禁通过`，退出码 `0`
- 失败：输出 `文档纪律门禁失败：` 并逐条列出 `[标签] 文件: 违规说明`，退出码 `1`

### 何时必跑

- **涉及文档改动后**：改了 `docs/反馈层/**` 或新增 `docs/**/*.md` 后
- **任务完成时**：在持久任务写回结果、状态和唯一下一步后
- **合并前**：含文档改动的分支合并回主分支前

### 失败处理

1. **优先清理违规**：按门禁输出修文档（改名/精简/移除时态标题/确认 gitignore）
2. **不得绕过**：禁止改脚本正则、删断言、临时注释让违规通过
3. **显式豁免**（仅极少数）：若某条纪律确需特定场景放宽，须在决策目录登记决策说明理由与影响范围，豁免点在脚本可追溯标注

### 维护规则

- 新增文档纪律约束时，优先扩本脚本断言，而非另起脚本
- 行数上限类断言（如简表 ≤ 15）按实际增长评估调整，调整时同步更新权威源（`交接.md` 维护说明）
- 权威源行号漂移时同步更新本文件断言清单引用

## 文档事实漂移门禁（check-doc-fact-drift.ps1）

> 解决"代码高频变动、文档低频滞后"导致的现状锚失真：v2 重写后文档仍引用已删的 `ChainExecutor`。
> 与文档纪律门禁互补：前者查"格式/纪律"，本门禁查"事实/存在性"。

### 断言清单

| # | 断言内容 | 豁免规则 |
|---|---------|---------|
| A | **带 `.java` 后缀的路径/文件名引用**：反引号包围的 `` `...Xxx.java` `` 引用，核对 basename 在 `src/main` 或 `src/test` 下是否存在 | ① 行级历史关键词（已删除/已删/删除/废弃/迁移前/曾被/曾经/历史/取代/替换为/改为）；② 历史快照文件整体跳过（见下）；③ 外部类白名单（JDK/Minecraft/GT/Mixin 等不在本项目 src 下的合法外部引用） |
| B | **裸 CamelCase 类名引用**：反引号包围的 CamelCase 标识符，核对 src 下是否存在同名 .java | 同断言A 豁免；另过滤明显非类名（单字母/全大写常量/小驼峰方法名/含 `.`/`/`/`-`/`_` 的路径配置键），并精确豁免历史控制协议标识符与 `RunId` |

### 文件级豁免（断言 A 与 B 整体跳过）

以下目录的 .md 文件视为历史快照/演进记录，引用当时存在但现已删/改的类属合法叙事，不参与漂移核对：

- `docs/反馈层/errors/*.md`（错误事件快照）
- `docs/反馈层/决策/*.md`（决策演进史，记录各阶段类名）
- `docs/诊断层/**/*.md`（审查报告、技术债计划、重构计划，均为时间点快照）

> 现状锚失真只针对"当前真理"文档：`NORTH_STAR.md` / `AGENTS.md` / `docs/设定值层/边界.md` /
> `docs/诊断层/项目结构.md` / `docs/传感层/门禁脚本说明.md` / `docs/设定值层/硬约束总目录.md` 等。

### 运行命令

```text
python scripts/run-agent-command.py repo-script check-doc-fact-drift
# 回归自测（协议标识符、虚构类与真实类）
python scripts/run-agent-command.py repo-script check-doc-fact-drift --self-test
```

- 通过：输出 `文档事实漂移门禁通过`，退出码 `0`
- 失败：输出 `文档事实漂移门禁失败：` 并逐条列出 `[事实漂移] 文件:行号: 引用类/文件 ... 在 src 下不存在`，退出码 `1`

### 何时必跑

- **涉及 src 类删除/新增/改包路径的改动后**：删/改/移动 .java 文件后必跑（最易触发漂移）
- **合并前**：与文档纪律门禁同级，合并回主分支前必跑
- **现状锚（边界.md / 项目结构.md）改动后**：现状锚自身是高频漂移源

### 失败处理

1. **优先修文档**：把引用更新到 v2 当前类名/路径（示例：把旧 `ChainExecutor` 改为 `ChainExecutionEventBridge`）
2. **不得绕过**：禁止改脚本正则放宽、删断言、临时注释让违规通过
3. **历史叙事用关键词标注**：若某条引用确实是叙述历史（"旧的 XxxYyy 已被替换为 ..."），在行内补历史关键词即可豁免
4. **外部类入库**：新引入外部依赖类导致误报时，加入脚本 `$externalAllowlist`（按库来源分组，附注释）
5. **显式豁免**（仅极少数）：若某条现状锚引用确需保留旧名，须在决策目录登记决策说明理由与影响范围，豁免点在脚本可追溯标注

### 维护规则

- `$externalAllowlist` 增长时按库来源分组并注释（JDK / Minecraft / Forge / GregTech / Mixin / 可选模组）
- 历史关键词列表增长时谨慎，避免误豁免真实漂移
- 现状锚文件清单变更（新增/移除"当前真理"文档）时同步更新本说明
