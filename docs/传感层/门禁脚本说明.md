# 验证边界说明

本仓不使用 grep 文档措辞、文件命名或 agent 环境文本的人工政策脚本充当技术正确性门禁。文档结构和协作约束由评审维护，不能把启发式文本匹配写成构建通过证明。

## 有效验证

| 验证 | 覆盖范围 | 不证明什么 |
|---|---|---|
| `./gradlew test` | 纯 JVM 单元、协议、结构和回归测试 | Minecraft 客户端实际加载与交互 |
| `./gradlew check` | Gradle verification lifecycle | 未纳入任务的人工运行态 |
| `./gradlew build` | 当前基线编译、测试和制品组装 | 其他 GTNH baseline 与发布成功 |
| `verifyGtnhBaseline` | manifest 声明与解析出的 GregTech 版本一致 | 完整 client/server 游戏流程 |
| branch CI matrix | `gradle/gtnh-baselines.json` 中每项 baseline 的 clean runner 验证 | 本机环境和 tag 发布结果 |
| 人工运行态 | 指定客户端、服务端、模组组合下的真实行为 | 未执行的版本与场景 |

`scripts/verify-gtnh-baselines.ps1` 是维护者可选的本地双 baseline 诊断入口；发布权威仍是 branch CI matrix 与 tag exact-SHA 门。OpenCode 命令继续通过 `python scripts/run-agent-command.py -- <executable> <args...>` 执行。

## 证据纪律

- 交付时区分静态检查、单元测试、Gradle verification、制品、CI 与人工运行态。
- 只报告实际执行过的命令、结果和制品身份；没有执行的层级写为未验证。
- 修改线程、网络、生命周期、渲染或可选模组加载边界时，按风险补定向测试和人工运行态矩阵。
- 发布前按 `docs/控制律层/发布流程.md` 和现行 workflow 核对，不以本地成功替代 CI 或 Release 证据。
