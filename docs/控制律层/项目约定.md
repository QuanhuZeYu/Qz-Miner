# 项目约定

本文件记录项目级、长期有效、且不适合直接塞进 `AGENTS.md` 的具体约定。

## 当前状态

- 缺陷修复优先采用工程级修复：先定位边界与同类风险，再收敛为可复用机制或稳定架构约束，避免只围绕当前堆栈做一次性小补丁。
- GT / BW / GT++ 普通矿的时运上限突破必须直接拦截 `fortune > 3`。同一 jar 保留 2.8 legacy 与 2.9 adapter 注入，plugin 按类字节码的方法 descriptor 选择，不能仅按类存在判断。
- 相关表达式注入依赖 `MixinExtras`，`mixins.qz_miner.json` 需要保留 `mixinextras.minVersion` 声明。
- GitHub release 标题统一使用 tag 名；`.changelogs/<tag>.md` 只负责 release 正文，不负责标题。
- `.changelogs/<tag>.md` 优先写用户可见变更和必要兼容说明，避免堆叠内部审查过程、验证细节、工具配置和后续待办；验证结论和协作细节应写入记忆、错误或审查文档。
- GTNH 支持 manifest 与预期 GregTech 版本集中在 `gradle/gtnh-baselines.json`；Qz-UILib 活动依赖为 `4.6.3:dev`，`gtnhsettingsconvention` 为 `2.0.25`。非平台硬依赖的整合包兼容依赖默认使用 non-publishable 配置，避免写入发布依赖。
- GTNH 默认开发/出包基线只由 `gradle.properties` 的 `elytra.manifest.version` 决定，且必须在清单中唯一命中；发布只产出该默认 manifest 构建的一套 jar，不按 GTNH 基线拆包。
- 外部 1.7.10 mod 进入 RFG dev runtime 时，优先依赖 `dev` classifier 或 Gradle metadata 中的 MCP 变体。Qz-UILib 的权威远端来源为 JitPack，活动配置使用标准坐标 `com.github.QuanhuZeYu:Qz-UILib:4.6.3:dev`，且不再提供 Maven Local/旧 group fallback；主动发布 GTNH Maven 不是 Miner 发布前置。运行时 `@Mod` 对 `qz_uilib` 保持 `required-after:qz_uilib@[4.6.0,)` 硬依赖，发布包不内嵌 UILib。JitPack 组合发布通道以 Build API 的 tag/public/commit 身份、canonical POM/main/`dev`/`sources` 内容与校验和，以及 clean 显式 `:dev` consumer 为放行证据；该通道 `.module` 返回 `404` 是预期，不混入普通 Maven Gradle Module Metadata 通道的规则。
- HUD 渲染统一交给 Qz-UILib 紧凑 HUD；Miner 只在客户端初始化期注册一次不可变 snapshot provider。断线/世界卸载不关闭注册，按键监听只更新业务状态，common/server 禁引用 `ui.hud.api`。
- 本模组配置权威文件为 `config/qz_miner.yaml`（UILib Schema + ConfigManager）；旧 `qz_miner.cfg` 只作一次性导入源，见 `docs/反馈层/决策/config-yaml-authority.md`。
- 所有生产配置管理器必须使用三参 bootstrap 注入 Qz-Miner 草稿校验器；原始 YAML 必须在 Authority 加载前经 NodeType preflight。current 的 `CommittedSnapshot` 仅作带单调 epoch 的派生发布令牌，不得写回 Authority/YAML 或参与非法值恢复。
- GTNH 体系下多数模组 Maven artifact 通常同时存在 `dev` classifier、`sources` classifier 和无后缀运行时发布 jar；开发编译/运行优先选 `dev` 或 MCP 变体，源码核对选 `sources`，生产整合包运行使用无后缀发布 jar，避免混用不同命名环境。
- GitHub Release assets 与 Maven Local 都不能替代依赖解析验收；Qz-UILib 的 channel-aware 放行规则及证据矩阵以 `docs/反馈层/决策/jitpack-release-dependencies.md` 为准，已发布 tag 不移动。所有 branch push/PR 由清单生成独立只读 clean-runner matrix，各 leg 串行执行 workspace setup、精确依赖断言、test、check、build；tag workflow 在副作用前机械要求同 SHA branch push CI 成功，tag 后仍须独立核验 tag 指向、Release 正文与 assets。
- OpenCode 默认使用内置 `build`；非平凡任务以 `.opencode/tasks/<id>.md` 持久化并登记 `INDEX.md`，不使用仓库自定义 agent、临时 task/handoff 或控制包。

## 适合写入本文件的内容

- 项目特有的模块拆分约定。
- 特定错误处理口径。
- 配置文件组织方式。
- 测试目录和命名口径。
- 文档命名和示例维护约定。

## 不适合写入的内容

- 通用 Git 规范、提交规范、语言通用规范。
- 当前任务状态或阶段计划。
- 一次性试验结论。
