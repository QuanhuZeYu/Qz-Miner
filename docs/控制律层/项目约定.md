# 项目约定

本文件记录项目级、长期有效、且不适合直接塞进 `AGENTS.md` 的具体约定。

## 当前状态

- 缺陷修复优先采用工程级修复：先定位边界与同类风险，再收敛为可复用机制或稳定架构约束，避免只围绕当前堆栈做一次性小补丁。
- GT / BW / GT++ 普通矿的时运上限突破，必须优先拦截上游 `getDrops` 中的 `fortune > 3` 截断，不能只通过重算 `Random.nextInt(...)` 参数实现。
- 相关表达式注入依赖 `MixinExtras`，`mixins.qz_miner.json` 需要保留 `mixinextras.minVersion` 声明。
- GitHub release 标题统一使用 tag 名；`.changelogs/<tag>.md` 只负责 release 正文，不负责标题。
- `.changelogs/<tag>.md` 优先写用户可见变更和必要兼容说明，避免堆叠内部审查过程、验证细节、工具配置和后续待办；验证结论和协作细节应写入记忆、错误或审查文档。
- 开发依赖基线当前同步到 GTNH `2.9.0-beta-1`、Qz-UILib `4.5.2` 与 `gtnhsettingsconvention` `2.0.25`，非平台硬依赖的整合包兼容依赖默认使用 non-publishable 配置，避免写入发布依赖。
- 外部 1.7.10 mod 进入 RFG dev runtime 时，优先依赖 `dev` classifier 或 Gradle metadata 中的 MCP 变体；Qz-UILib `4.5.2` 当前按 `devOnlyNonPublishable("com.github.QuanhuZeYu:Qz-UILib:4.5.2:dev")` 接入。运行时 `@Mod` 对 `qz_uilib` 为 `required-after` 硬依赖（发布包仍不内嵌，由 modpack 安装）。
- 本模组配置权威文件为 `config/qz_miner.yaml`（UILib Schema + ConfigManager）；旧 `qz_miner.cfg` 只作一次性导入源，见 `docs/反馈层/决策/config-yaml-authority.md`。
- 所有生产配置管理器必须使用三参 bootstrap 注入 Qz-Miner 草稿校验器；原始 YAML 必须在 Authority 加载前经 NodeType preflight。`currentValidatedSnapshot` 仅作派生发布，不得写回 Authority/YAML 或参与非法值恢复。
- GTNH 体系下多数模组 Maven artifact 通常同时存在 `dev` classifier、`sources` classifier 和无后缀运行时发布 jar；开发编译/运行优先选 `dev` 或 MCP 变体，源码核对选 `sources`，生产整合包运行使用无后缀发布 jar，避免混用不同命名环境。

## 适合写入本文件的内容

- 项目特有的模块拆分约定。
- 特定错误处理口径。
- 配置文件组织方式。
- 测试目录和命名口径。
- 文档命名和示例维护约定。

## 不适合写入的内容

- 通用 Git 规范、提交规范、语言通用规范。
- 当前任务状态或阶段计划。
- 一次性试验结论。
