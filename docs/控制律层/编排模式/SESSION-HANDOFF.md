# 跨会话交接模式

> 本文件定义长任务的易失会话工作记忆。主动、结构化交接用于降低上下文压缩造成的信息丢失；新会话必须先核对再续接。

## 1. 状态边界

| 层次 | 载体 | 寿命 | 内容 |
|---|---|---|---|
| 项目状态 | `docs/反馈层/交接.md` | 跨任务、长期 | 项目阶段、未收敛项、待用户决定事项 |
| 活动任务 | `.opencode/task.md` | 单任务、易失 | 当前目标、范围、动作、验收、验证和结果 |
| 会话工作记忆 | `.opencode/session-handoff.md` | 单任务、易失 | 已验证事实、剩余动作、未决决定和必要纠偏信息 |

活动任务单格式见 [`TASK-BRIEF.md`](TASK-BRIEF.md)。handoff 不替代活动任务单或项目交接；任务完成后，只有对未来有持续价值的事实才回流到项目文档。

## 2. 触发时机

- 用户说“停”“保留”“开新会话”或“先记下来”时，立即写 handoff
- 上下文较大或多轮纠偏后，主 agent 用中文提醒用户考虑交接，不擅自中断
- 即将转入用户实机、merge、push、tag 或 release 时，在洁净提交检查点提醒一次

## 3. 写入内容

`.opencode/session-handoff.md` 使用覆盖式维护，只保留：

- 活动任务单绝对路径与当前目标
- 已验证事实及关键 `file:line`
- 已完成改动和验证结果
- 剩余动作、待验证项和未决用户决定
- 有持续价值的失败原因或被否决方案

不记录工具原始输出、大块文件内容、已完成且无后续价值的过程、调用谱系、固定尝试计数或旧 `task_id`。任何 Task 调用返回后，旧 `task_id` 都不得复用；后续工作通过覆盖为更窄的任务单并创建全新 task 继续。

## 4. 新会话冷启动

1. 读取 `.opencode/session-handoff.md`、`.opencode/task.md`、`docs/反馈层/交接.md` 和 [`SUBAGENT-ORCHESTRATION.md`](SUBAGENT-ORCHESTRATION.md)。
2. 核对当前分支、HEAD、工作区，以及 handoff 中关键路径和 `file:line`。
3. 核对任务单目标、写集、验收和验证是否仍适用，确认是否出现用户保留决策。
4. 无漂移时向用户说明接续位置和下一步，然后自动推进；有漂移时先更新任务单或 handoff，再继续。
5. 所有后继子任务都创建全新 task，只传任务单路径和一句执行指令。

handoff 也是模型产出，不能替代代码、Git 和权威文档。关键事实缺失时视为未知，不凭记忆补齐。

## 5. 任务完成清理

- 删除或重置无持续价值的 `.opencode/session-handoff.md` 内容
- 对拟回流事实逐项确认：会指导哪个未来决策、属于哪个权威文档、删除后会重复造成什么问题；答不上则丢弃
- 将仍未收敛且跨任务有效的业务状态更新到 `docs/反馈层/交接.md`
- 运行 `pwsh -NoProfile -File scripts/check-doc-discipline.ps1`

会话记录是易失工作记忆，不应沉淀为项目流水账。
