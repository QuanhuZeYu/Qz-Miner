# 默认 build 持久工作流

## 1. 执行主体与入口

仓库使用 OpenCode 内置默认 `build` 直接完成分析、设计、实施、自审、验证与提交，不定义仓库级自定义 agent。入口按工作量分为：

- **CHAT**：简单问答、单次只读定位或无需跨轮保存的讨论；不创建任务文件。
- **DESIGN**：需要跨轮澄清、设计或取舍；创建 `DRAFT` 持久任务，未确认目标、范围和验收前不得写盘实施。
- **EXECUTE**：目标、非目标、写集、验收和授权验证均已确认；任务先进入 `READY`，开始写盘前由当前 build 取得所有权并改为 `ACTIVE`。

简单任务可以从 CHAT 直接完成；一旦需要跨轮恢复、非平凡写盘或提交，就必须进入持久任务。

## 2. 四层记忆

- **L0 会话缓存**：工具输出、临时推理与当前操作上下文；易失，不作为事实源，不要求写回。
- **L1 任务工作记忆**：`.opencode/tasks/<id>.md`；保存任务元数据、设计、范围、进度、证据、唯一下一步与结果，可提交并用于无旧聊天恢复。
- **L2 项目语义记忆**：`NORTH_STAR.md`、`AGENTS.md` 与 `docs/` 权威文档；保存跨任务稳定的约束、决策和业务状态，不复制任务流水。
- **L3 情景档案**：`docs/反馈层/errors/`、`docs/诊断层/reviews/` 与历史决策演进；保存可复用的事故、审查和决策证据，不承担当前任务状态。

恢复顺序固定为：仓库规则与权威文档 → `.opencode/tasks/INDEX.md` → 目标任务文件 → 实时 Git。L0 只能加速，不得覆盖 L1-L3 或 Git 事实。

## 3. 状态机与所有权

状态只允许 `DRAFT`、`READY`、`ACTIVE`、`BLOCKED`、`DONE`、`CANCELLED`：

`DRAFT → READY → ACTIVE → DONE` 是正常路径；信息不足可由 `DRAFT/READY/ACTIVE → BLOCKED`，条件恢复后回到 `READY`；放弃任务进入 `CANCELLED`。完成态不再恢复，后续修正建立新任务。

- 同一任务同时只能有一个 owner；`ACTIVE` 必须记录当前 owner 与开始时间。
- build 开始前核对分支、HEAD、工作区与写集；已有改动必须识别并保留。
- 写集不足、目标含糊、公共 API/依赖版本/发布取舍未决时，保持零写或停止新增写盘，记录阻断并设为 `BLOCKED`，返回 `INCOMPLETE`。
- `INDEX.md` 是任务发现入口，不复制任务正文；状态变化时同步索引。

## 4. 阶段写回

1. **设计确认**：写回已确认设计、非目标、写集、验收与风险；满足执行条件后改 `READY`。
2. **开始实施**：核对实时 Git 后记录基线、owner 和唯一下一步，改 `ACTIVE`。
3. **阶段边界**：每完成一个可验证单元，写回进度、证据和新的唯一下一步；禁止并列多个“下一步”。
4. **阻断**：记录触发条件、已保留现场和解除条件，改 `BLOCKED`；不得把未执行验证写成通过。
5. **完成**：自审任务 diff，执行获授权验证，记录真实结果、残余风险和提交信息，改 `DONE`；稳定事实再按归属回流 L2/L3。

## 5. 验证与自审

默认 build 只执行任务文件明确列出的验证。有限 Gradle 仅在任务处于 `ACTIVE` 且验证清单明确授权时，经 `scripts/run-gradle-opencode.py` 进入 `qz-gradle-opencode/v1` 的 `start/poll/wait/self-test`；禁止直接 PowerShell、wrapper、自造进程、并行构建、kill、`--stop`，运行态与双基线仍交用户。

环境所有权保持只读：本机环境归用户、CI 环境归 runner；build 不设置、覆盖、清空或持久化环境变量，不用 Gradle/JDK home 参数绕过异常。缺少前提时记录 `BLOCKED` 并返回 `INCOMPLETE`。

提交前 build 必须回读任务、检查完整 diff 与 status，逐项核对目标、非目标、写集、验收、风险、I1-I10 和验证证据。关键发布或需要上下文隔离时，可由用户另开会话或安排外部 review；这不改变当前 build 对自审真实性的责任。
