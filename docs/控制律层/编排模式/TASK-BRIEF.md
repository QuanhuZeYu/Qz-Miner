# 活动任务单规范

## 1. 唯一载体

非平凡任务使用仓库根下 `.opencode/task.md` 作为唯一活动任务单。该文件被 Git 忽略，不进入提交；同一时间只维护一份，任务完成后可删除或由下一任务覆盖。

任务说明优先使用中文。主 agent 派发子 agent 时只传任务单绝对路径和一句执行指令，不复制任务正文。

## 2. 固定结构

任务单保留以下八个必需二级章节，并可在“验收”后增加一个可选“风险”章节（风险不计入八个必需章节）：

```markdown
# 当前任务：简短标题

## 目标
- 可观察的最终结果。

## 非目标
- 本次明确不处理的事项。

## 写集
- `允许修改的仓根相对路径`。

## 已验证事实
- 已由代码、文档、Git 或工具核实的事实。

## 动作
1. 按文件写明具体改动。

## 验收
- A1：可观察且可判定的通过条件。

## 风险
- R1：可选；需要 reviewer 特别核对的具体风险。

## 验证
- `可直接执行的命令`。

## 结果
- 待执行。
```

写集必须完整且明确。fixer 发现必要改动不在写集时保持零写并返回 `INCOMPLETE`，不得自行扩展。

验收项使用轻量 ID `A1`、`A2`……；风险项可选，使用 `R1`、`R2`……。这些 ID 只供 reviewer 在 finding 中追溯，不要求机器解析，也不承载哈希或机械状态。

## 3. 执行与复审

fixer 读取任务单后只修改写集，执行“验证”中的必需命令，按项目 Git 规范提交，并在“结果”写中文简要回执。回执至少记录改动文件、验证结果和提交标识。

写盘改动必须由 reviewer 独立复审。reviewer 读取同一任务单与 Git diff，核对目标、非目标、写集、验收、风险、验证和硬约束，按 P0/P1/P2 用中文输出；无问题时明确说明未发现问题及残余风险。

## 4. 纠偏

任何 Task 调用返回后，旧 `task_id` 不得复用。需要纠偏、重试或继续时，主 agent 将已验证事实写回任务单，删除已完成动作，将目标、写集、动作、验收与验证覆盖为更窄的剩余范围，然后创建全新 task。

任务单不得承载哈希绑定、调用谱系、固定尝试计数或机械状态记录。跨会话只在 `.opencode/session-handoff.md` 保留继续任务所需的最少事实，且同样不得复用旧 `task_id`。
