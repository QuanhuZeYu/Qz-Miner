# 持久任务单规范

## 1. 载体与命名

需要跨轮恢复、非平凡写盘或提交的任务使用 `.opencode/tasks/<id>.md`，并登记到 `.opencode/tasks/INDEX.md`。任务文件可提交；一个任务只使用一个文件，不另建 handoff、控制包或临时活动任务。

`<id>` 使用稳定的 `YYYYMMDD-kebab-case`。简单问答和一次性只读定位不创建任务；跨轮设计先创建 `DRAFT`，目标、范围、验收和验证确认后再进入执行。

## 2. 状态与元数据

状态只允许：

- `DRAFT`：设计或范围仍在形成，不得实施。
- `READY`：执行合同完整，等待取得所有权。
- `ACTIVE`：默认 build 已核对实时 Git 并正在执行；唯一允许写盘和使用任务授权验证的状态。
- `BLOCKED`：缺少事实、决策、权限或外部证据；记录解除条件并返回 `INCOMPLETE`。
- `DONE`：验收、自审、验证、结果和提交均已完成。
- `CANCELLED`：任务已放弃，不再恢复。

元数据至少包含 ID、状态、owner、创建日期、基线分支与 HEAD；`ACTIVE` 还要记录开始日期。状态或唯一下一步变化时同步 `INDEX.md`。

## 3. 固定结构

```markdown
# 任务：简短标题

## 元数据
- ID、状态、Owner、日期、基线分支与 HEAD。

## 目标
- 可观察的最终结果。

## 非目标
- 本次明确不处理的事项。

## 已确认设计
- 已由用户或权威事实确认的实现/兼容取舍。

## 写集
- 允许修改的仓根相对路径；必须完整明确。

## 验收
- A1：可判定的通过条件。

## 风险
- R1：触发条件、影响和处理边界。

## 进度与证据
- 已完成阶段、命令、输出摘要与证据等级。

## 验证
- 获授权且可直接执行的命令；没有则明确写无。

## 唯一下一步
- 只能有一项可立即执行的动作；完成态写“无”。

## 结果
- 真实文件、验证、残余风险与提交信息。
```

风险章节可以写“无”，其余章节不得省略。禁止把未执行验证写成通过，也不得用静态核对替代 CI、制品或运行态证据。

## 4. 执行纪律

- 开始前读取仓库规则、相关权威文档、任务、索引与实时 Git；保留用户改动。
- 默认 build 只修改写集。写集不足、目标含糊、公共 API/依赖版本/发布取舍未决时保持零写或停止新增写盘，设为 `BLOCKED` 并返回 `INCOMPLETE`。
- 每个可验证阶段结束时写回进度、证据和唯一下一步，确保不依赖旧聊天即可恢复。
- 任务明确授权有限 Gradle 时，只能在 `ACTIVE` 状态经 `scripts/run-gradle-opencode.py` 进入 `qz-gradle-opencode/v1`；其他边界见稳定命令。
- 完成前回读任务与完整 Git diff，自审目标、非目标、写集、验收、风险、I1-I10 和验证真实性；按 Git 规范提交后写回提交标识，状态改 `DONE`。
- `DONE/CANCELLED` 不恢复；后续修正建立新任务，不改写完成任务的历史结果。
