# 稳定命令

本文件记录项目可长期复用的构建、检查、测试和运行命令。

## 当前状态

- 当前项目使用 Gradle Wrapper 和 Kotlin DSL 构建脚本。

## 环境前提

- 环境所有权遵循 `AGENTS.md`「控制律层·环境所有权」：本机归用户、CI 归 runner，agent 只读核验，禁止赋值、持久修复或用 Gradle home/JDK 参数绕过。
- 执行依赖环境的命令前，仅逐项读取任务所需的非敏感变量；敏感变量只查存在性且不回显。缺失或异常时停止命令，返回 `INCOMPLETE` 并询问用户。

## 默认候选

> 本节原始 Gradle Wrapper 命令仅供用户、维护者或 CI；agent 必须使用下方 OpenCode 有界协议。

- 构建检查：`.\gradlew.bat check`
- 打包：`.\gradlew.bat build`
- 测试：`.\gradlew.bat test`
- 客户端运行：`.\gradlew.bat runClient`
- 服务端运行：`.\gradlew.bat runServer`

## 当前已验证

- 编译：`./gradlew.bat compileJava`
- Java 21 客户端启动回归：`./gradlew.bat runClient21`
- 现代 Java dedicated server 启动回归：`./gradlew.bat runServer25`
- Java 21 dedicated server 备选启动回归：`./gradlew.bat runServer21`
- GTNH 2.8.4/2.9.0-beta-1 双基线：`./scripts/verify-gtnh-baselines.ps1`
- 推送分支：`git push origin <当前分支>`
- 推送 tag：`git push origin <tag>`

## OpenCode 有界 Gradle 协议

- 唯一入口为 `qz-gradle-opencode/v1`，合同见 [`Windows-Gradle执行协议.md`](Windows-Gradle执行协议.md)。fixer 用脚本 `Start/Poll/Wait`，不得直接 wrapper；reviewer 仅按合同复验，explorer 仅诊断既有 RunId，其他 agent 禁止。
- 普通编译 Start：`& .\scripts\run-gradle-opencode.ps1 -Action Start -GradleArgs @('compileJava')`
- 普通测试 Start：`& .\scripts\run-gradle-opencode.ps1 -Action Start -GradleArgs @('test')`
- 普通检查 Start：`& .\scripts\run-gradle-opencode.ps1 -Action Start -GradleArgs @('check')`
- 目标测试 Start：`& .\scripts\run-gradle-opencode.ps1 -Action Start -GradleArgs @('test', '--tests', '<类名或类名.方法>')`
- 查询：`& .\scripts\run-gradle-opencode.ps1 -Action Poll -RunId '<RunId>'`
- 等待：`& .\scripts\run-gradle-opencode.ps1 -Action Wait -RunId '<RunId>' -WaitSeconds 30`
- 多项 Gradle 参数必须在当前 PowerShell 进程中用调用运算符 `&` 传数组；不得使用外层 `pwsh -File ... -GradleArgs @(...)`，因为该方式不能可靠传递该数组。
- 自测（不调用 Gradle）：`& .\scripts\run-gradle-opencode.ps1 -SelfTest`。
- `runClient*`/`runServer*` 交用户执行；`verify-gtnh-baselines.ps1` 暂不授权给 agent。

## 双基线验证

- `GRADLE_USER_HOME` 由用户在 agent 外部预先配置为纯 ASCII 路径；agent 仅只读核验。
- 脚本逐个 baseline 先用 `dependencyInsight` 断言 GT5-Unofficial 精确版本，再串行执行 `clean test compileJava check`；2.8.4 对应 `5.09.51.482`，2.9.0-beta-1 对应 `5.09.52.594`。
- 默认开发与最终唯一 jar 使用 2.9.0-beta-1；2.8.4 是最低兼容编译/测试基线。脚本使用单次 daemon 并在版本间停止 daemon，避免 Windows 锁住 `build/rfg`。

## 服务端验证注意事项

- 普通 `./gradlew.bat runServer` 不适合验证 Java 17-25 / `lwjgl3ify` 服务端链路；当前会走到不支持 server launch 的 relauncher 路径。
- `runServer25` / `runServer21` 使用 modern Java、`lwjgl3ify` 与 Hodgepodge，是当前服务端启动回归优先入口。
- 若 dev 环境同时启用 ServerUtilities 与 Et Futurum，需要在 `run/server/serverutilities/serverutilities.cfg` 中关闭 `B:enable_player_sleeping_percentage=false`，否则会在 Qz-Miner 初始化前触发两者睡眠百分比 mixin 冲突。

## 实机运行日志位置（真机回归传感读数来源）

> 真机回归跑完后，主 agent 直接对照下列日志确认行为，**不需用户主动贴**。日志文件大或不确定 batch 何时跑完时，派 `@explorer` 批量检索。

### `runClient21` 客户端日志（Windows 路径，相对项目根）

主目录：`run/client/logs/`

| 文件 | 用途 | 说明 |
|---|---|---|
| `fml-client-latest.log` | **主诊断入口**（含所有 `[qz_miner/]` 日志：`[ChainStateMachine] transition`/`[ChainPhaseSnapshot]`/`[ParallelTick]`/`[ChainDropCollector]`/`[ChainPreview]`/`[Network]`/`[Compat][Ore]`/`[PlayerManager]`/`[EventSystem]` 等） | 最新一次客户端启动的完整 FML 日志，启动时滚动覆盖到 `fml-client-1.log` 等 |
| `fml-client-1.log`/`-2`/`-3` | 历史滚动备份 | 越早编号越旧，用于回看上一次实机 |
| `latest.log` | minecraft 主日志子集 | 体量小，含 `Reloading ResourceManager` 等基本信息 |
| `GregTech.log` | GregTech 独立日志 | 含矿石生成/扫描等，矿石连锁调试补充 |
| `LootGames.log`/`Explosion.log` | 其他 mod 专有日志 | 对应 mod 触发时才有内容 |
| `fml-junk-earlystartup.log` | 早期启动阶段 | 启动早期 FML 自身诊断 |

**关键 qz_miner 日志特征串**（rg/grep 抓诊断）：
- 状态机转移：`[ChainStateMachine] transition <from> -> <to> on <Event> gen=N player=<UUID>`
- PlanCancelled 根因（commit b3a1c68 起带 reason）：`[ChainStateMachine] PlanCancelled reason=<reason> gen=N player=<UUID>`
- 玩家登录/登出：`[PlayerManager] Player logged in: <name>` / `[PlayerManager] Exiting to main menu, clearing N player(s)`
- 模式切换：`[KeyListener] Switched (sub|chain) mode to <X>`
- 预览任务：`[ParallelTick] Registered CLIENT_PRE task: chain-preview-<x>-<y>-<z>`
- 适配器降级（守信条六「降级需显式」）：`[Compat][Ore] Ore adapter degraded - both classes unresolved: ...`
- 配置同步拒绝（限频汇总，非逐包成功日志）：`[ChainConfigSync] Client dispatcher rejected N packet(s); dropped without cross-lifecycle retry`
- 客户端 UILib 集成完成：`[ClientInit] stage=uilib-integrations-ready`
- Fortune Mixin 能力门：`[Compat][Fortune] mixin=... target=... apply=... reason=...`
- 自动工具客户端静默决策：`[AutoToolSwapClientDiag] reason=cycle-disabled|cycle-ineligible|held-usable|no-candidate|takeover-disabled|takeover-inventory-unsafe|takeover-no-candidate|takeover-request-ignored`
- 自动工具松键事实采样失败：`[AutoToolSwap] release fact capture failed; preserving round for retry`（保留旧 round/ledger，等待后续有效 tick 恢复）

### `runServer25` 服务端日志

主目录：`run/server/logs/`（与 client 对称；**当前未跑过 runServer25，目录首次跑会自动创建**）

| 文件 | 用途 | 说明 |
|---|---|---|
| `fml-server-latest.log` | **主诊断入口**（同 client 的 `fml-client-latest.log`，含所有 `[qz_miner/]` 日志） | 服务端独有玩家登录/切维度的服务端侧诊断 |
| `latest.log` | minecraft 主日志子集 | 同 client |

诊断特征串与 client 一致；服务端独有的如 `[PlayerManager] Player logged in` 在服务端更早出现。

### Native 崩溃日志

若 JVM 崩溃（少见，但 mixin/ASM 错误可能触发）会在项目根或 `run/client/`/`run/server/` 生成 `hs_err_pid*.log`。这种情况派 `@explorer` 或 `@oracle` 优先看该文件 stacktrace。

## Issue 症状路由（维护者内部）

> 玩家提交 Issue 时只需描述遇到的问题并上传手边对应的最新日志，不必筛选时段、marker 或分析内容。下表是维护者内部的排查入口，不是玩家提交清单：维护者负责从日志中筛选与症状直接相关的时段和 marker；上下文仍不足时，再围绕具体 Issue 补最小埋点或提出单点追问，不要求玩家执行测试或填写环境矩阵。

| 玩家描述的症状 | 优先日志 | 优先检索的 marker / 信息 |
|---|---|---|
| 启动失败、界面初始化失败、HUD 不显示或渲染异常 | 对应侧 `fml-*-latest.log`；JVM 崩溃时再看 `hs_err_pid*.log` | FML stacktrace、`[ClientInit]`、Qz-UILib 初始化异常、`[ChainPreview]` |
| 连锁不启动、中断、范围或预览异常 | 对应侧 `fml-*-latest.log` | `[ChainStateMachine]`、`[ChainPlanDiag]`、`[ChainWatchdog]`、`[ChainPreview]`、`[ParallelTick]` |
| 掉落数量、聚合或释放异常 | 服务端或单人客户端 `fml-*-latest.log` | `[ChainDropCollector]`、对应时段的 `[ChainStateMachine]` / `[ChainWatchdog]` |
| 自动工具未接替、错误换位或未恢复 | 对应侧 `fml-*-latest.log` | `[AutoToolSwapDiag]`、`[AutoToolSwapClientDiag]`、`[AutoToolSwap] release fact capture failed`；若有扩展 ID 越界异常，核对 `blockId/metadata/max`，若旧 round 长期停在 `CLOSING ledger=true`，沿同一 round 查 RESTORE/CLOSE |
| 配置未生效、不同步或方块 Picker 异常 | 对应侧 `fml-*-latest.log` | `[ChainConfig]`、`[ChainConfigSync]`、`Block picker degraded`、相关 stacktrace |
| GT 线缆替换、连接刷新或矿石时运异常 | 服务端或单人客户端 `fml-*-latest.log`；必要时补看 `GregTech.log` | `[CableCompat]`、`[CableReplace]`、`[Compat][Ore]`、`[Compat][Fortune]` |
| 多人连接、客户端与服务端状态不同步 | 客户端与服务端 `fml-*-latest.log` 中与症状直接相关的一侧或时段 | `[Network]`、`[ChainConfigSync]`、对应时段的状态机 marker |
| 登录、退出、重生、切维度或退主菜单后状态残留 | 对应侧 `fml-*-latest.log` | `[Lifecycle]`、`[PlayerManager]`、`[ChainStateMachine]`、`[ParallelTick]` |

日志取用遵循隐私最小化：维护者从报告者上传的对应日志中筛选相关时段或 marker；上下文确实不足时，才围绕该 Issue 做最小诊断补强或定向请求一个具体文件，不把分析与测试工作转交报告者，也不默认索取客户端与服务端双侧材料。
