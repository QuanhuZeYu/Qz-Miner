## 文档职责分工

文档之间不建立「上位压过下位」的效力排序：实际行为与构建状态以当前源码、配置与验证结果为准；工程边界与协作方式以 AGENTS.md 为准；对外契约以对外文档为准——实现与文档不一致时应指出偏差，不能仅因代码已如此实现而视为规范已变更；历史记录（反馈层踩坑、任务单、验收结论）只证明当时做过什么、验证到什么程度，不构成现行要求。

- 实时源码及其注释：行为、契约边界、实现细节与失败语义写在最近的代码处。
- [AGENTS.md](../AGENTS.md)：项目边界、高影响安全边界、工作方式与验证口径。
- [框架指导（包级原则）](../src/main/java/club/heiqi/qz_miner/chain/package-info.java)：本包及其子包共享的权限与真源划分原则——唯一写权威／边界不越权／协作式取消／跨线程只经事件总线／生命周期收口／复用既有入口／显式收尾，每条均标注派生自哪条用户偏好。
- [公共接口与兼容边界.md](开发者文档/公共接口与兼容边界.md)：对外稳定边界——哪些可依赖、哪些明确不稳定、兼容范围与变更处理。

持续有效的设计意图、契约边界与失败语义写在最近的代码注释处；施工过程与一次性结论不进长期资料，需要跨轮恢复时写短任务笔记。

## 构建与验证

- 完整构建（代码改动的交付门槛）：`gradlew.bat build`（Windows）/ `./gradlew build`（Unix），经仓库自带 wrapper 执行，不使用系统 Gradle。
- 本地开发件：`libs/qz_uilib-<版本>-dev.jar` 经本地文件解析消费，不等同于 Qz-UILib 的正式 Release 资产。
- CI（`.github/workflows/branch-ci.yml`）按 `setupCIWorkspace` → `test` → `check` → `build` 顺序执行；本机复现以 `build` 为准。
- 实机运行（`runClient21` 等）与发布动作交用户或 CI，agent 不自动执行。
