## 职责分工

文档之间不建立「上位压过下位」的效力排序，各类资料分工如下：实际行为与构建状态以当前源码、配置与验证结果为准；工程边界与协作方式以 AGENTS.md 为准；设计要求与契约以本文件标记为现行规范的文档为准——实现与规范不一致时应指出偏差，不能仅因代码已如此实现而视为规范已变更；历史记录（规划、任务单、台账、验收、踩坑）只证明当时做过什么、验证到什么程度，不构成现行要求。

- 实时源码及其注释：行为、契约边界与失败语义写在最近的代码处。
- [AGENTS.md](../AGENTS.md)：项目边界、高影响安全边界与工作方式。
- [框架指导（包级原则）](../src/main/java/club/heiqi/qz_miner/chain/package-info.java)：本包及其子包共享的权限与真源划分原则——唯一写权威／边界不越权／协作式取消／跨线程只经事件总线／生命周期收口／复用既有入口／显式收尾，每条均标注派生自哪条用户偏好。
- 根 [README.md](../README.md)：使用者可见的行为、模式与配置的对外说明。
- [使用文档/](使用文档/)：配置项语义与 5.3 联机版本边界。
- [开发者文档/开放化调整.md](开发者文档/开放化调整.md)：对外稳定边界——哪些是对外入口、哪些只是内部实现。
- [反馈层/errors/](反馈层/errors/)：历史踩坑根因与处置结论，只证明当时做过什么、验证到什么程度。

实现细节与一次性施工结论写在最近的代码注释处，不单独立页。
