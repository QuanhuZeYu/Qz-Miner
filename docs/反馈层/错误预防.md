# 错误预防清单

本文件按类别沉淀历次踩坑提炼的「正确处理方式」，供后续开发对照预防。
个案流水账已清除，只保留每类通则；新增可复现错误时只增补通则条目，详情落 `docs/反馈层/errors/ERROR-*.md`。

> **上溯规则**（守 AGENTS.md 4.3）：同类误差第 2 次出现时，应上溯评估是否需补一条不变量（`NORTH_STAR.md`）或补一道门禁（传感层），而非仅再记一条通则。本清单的多数通则已上溯为 `NORTH_STAR.md` 不变量 I1-I10。

## 掉落缓冲与延迟释放

- 玩家资产级缓存（掉落等）禁绑定到单次会话运行态；挂玩家级或全局级稳定宿主（`ChainPlayerDropBuffer`）
- 延迟释放机制必须先明确"宿主是谁"和"宿主提前结束时如何兜底"（当前位置 → 重生点 → 出生点 → 告警丢弃）
- 先清空再释放的资源流程必须具备失败回滚（`spawnEntityInWorld` 失败/异常时回填缓冲）
- 守 I5；详情：`errors/ERROR-20260528-session-drop-buffer-coupling.md`、`errors/ERROR-20260605-chain-drop-final-target-race.md`

## 并行线程与执行态收口

- 并行规划线程不得直接结束可能正由主线程执行器消费的会话；队列为空 ≠ 无目标在执行
- 涉及世界写入/掉落事件的执行状态收口必须放主线程执行驱动：v2 主线程 `ChainExecutionEventBridge.consumeContext` 消费 `ChainExecutionContext` 队列，worker 完成遍历 + 队列空后 `publish ExecutionFinished`，状态机 T7 RUNNING→FINISHING 收口（详见 `docs/反馈层/决策/chain-event-bus.md` 阶段5 C 段）
- 并行任务取消走协作式安全点，禁超时强杀 / `Future.cancel(true)` 常规取消 / 主线程绕过 `endStage` 屏障
- 订阅安装、外部取消与 worker 完成须在同一单调终局上线性化；外部取消胜出后 worker 静默终止，完成胜出后先观察合法完成事件再收口
- 完成 publication 必须先成功入队，再固化 count/terminal，并最后写可见完成标志；publication 抛错须保持 ACTIVE 并走单次取消事件，禁止留下“本地已完成、总线无完成事件”的中间态
- 规划 `confirmedCount` 的唯一写点必须在各 `BudgetedChainTraverser` 成功 `consumer.accept` 后；生产 consumer 只负责真实入队，不得二次计数。达到 `maxTargets` 时真实 queue、confirmed 与完成事件数量必须精确一致；取消路径不补数。客户端预览 origin 的单独投影计数是独立语义，不得顺手删除
- 守 I1/I2/I9/I10；详情：`errors/ERROR-20260605-chain-drop-final-target-race.md`、`errors/ERROR-20260718-auto-tool-empty-hand-priority.md`、`errors/ERROR-20260718-auto-tool-close-planning-publication.md`

### 候选预算折扣必须事务化并绑定 planning context

- 跨 slice/tick 的计费余数必须归单次 planning context，不能放入每片重建的 control/work budget，也不能由各 traverser 分别保存；自然完成时尾余数不补收、不跨玩家、round 或预览复用。
- 候选事务先检查 cancel/`shouldYield()`，再读取当前世界事实。配额边界必须先成功扣正预算、再提交余数和游标；失败不得改变 cursor、visited、frontier、queue 或 confirmed，下一片重读同一坐标。
- 空气折扣只能匹配本次读取精确等于 `Blocks.air`；null、液体、基岩、matcher=false 与模组 air-like 方块不能冒充。空气提交后不调用 candidate filter、matcher/consumer 或入队；AREA 继续空间扫描，CHAIN/Logging/GT 不扩展该节点。
- target 事务可合并生成/队首与首次 candidate 判定，但 duplicate、frontier 轮转、shell/slice 切换、GT 方向解析、matcher 与 consumer 仍独立正常收费。shell/slice 入口扣费必须在线性化后保存已初始化状态，避免 work budget=1 每片重复入口扣费而永久让出。
- 守 I2/I3/I9；详情：`errors/ERROR-20260725-air-budget-boundary-resume.md`；决策：`决策/planning-air-budget.md`

## 可选模组反射安全

- 可选模组兼容层禁用会扫描整类公开成员的反射 API（`Class#getMethod`）作为初始化路径——会解析客户端签名致 dedicated server 崩溃
- 类探测用 `Class.forName(name, false, loader)` 不触发静态初始化；成员解析沿 declared 层级、吞 `LinkageError`/`SecurityException` 并降级
- 客户端/服务端共包但签名含客户端类的第三方类，按稳定数据结构解析，不纳入服务端启动路径
- capability profile 的 required 成员必须同时核对调用语义与真实声明 owner；不得从相邻接口猜 owner，也不得把红石/邻居通知等非核心能力并入线缆替换 all-present 门
- 守 I6；详情：`errors/ERROR-20260601-lootgames-server-client-signature.md`、`errors/ERROR-20260609-gtnh-29-ore-adapter-api.md`、`errors/ERROR-20260706-cable-replace-binding-npe.md`

### TileEntity 身份必须在 seed 最后存活窗口纯值化

- 破坏后异步 drain 的事件链不得只传播 block/metadata 再尝试回读 origin TileEntity；必须在主线程、origin 被移除前捕获不含游戏对象/反射对象的不可变身份 token。
- 服务端 `RIGHT_CLICK_BLOCK` 回调是动作生效前 seed 的最后存活窗口；publish 前冻结 block、完整非负 int metadata 与 token，后续规划不得因“仍在主线程”就用动作后的 world 覆盖。任何读取异常标记 `UNRESOLVED` 并 fail-closed
- 身份比较先守 block/metadata 精确门，再比较 token；缺失、读取失败与单边 TileEntity 都不得作为通配符。已识别 adapter 失败必须 `UNRESOLVED`，禁止退回 runtime class 掩盖错误。
- 未识别模组可按 runtime type name 保持保守兼容，但不能为单个模组在生产 matcher 中增加字符串白名单；候选侧读取 live TileEntity 后立即纯值化，且不得把当前只读 World 边界夸大成全量快照。
- 详情：`errors/ERROR-20260720-tile-identity-seed-loss.md`

## 网络与生命周期线程收口

- `SimpleNetworkWrapper` 服务端入包与客户端状态同步必须经 `ServerMainThreadDispatcher`/`ClientMainThreadDispatcher` 收口后再碰主线程语义状态
- 高频率/可被远程放大的入包不得每包无界入 FIFO；应按端点 keyed latest-wins 背压（固定容量、tick 预算 drain、replace/remove 线性化、弱引用对象 identity、弱持有会话、过期弱键可回收、消费时重取并校验实例身份、START keyed drain 不可重入），诊断限频/汇总；线性化契约为「最后线性化成功值最终执行」，勿写「每个 submit true 最终可达」
- 客户端 S2C / 生命周期须绑定**真实连接 identity**（`INetHandler` 对象 `==`，非 identityHashCode/equals）与不可复用 connection/world generation；config 用 connection-active gate，phase/preview 用 world-active gate；toolswap 四个 S2C 传 `ctx.netHandler` 后 `captureForConnection`，禁全局 capture 误绑新连接；旧连接迟到 disconnect/cleanup/包 no-op；`ClientConnectionLifecycle` connect/bindWorld 返回转移结果，仅 transitioned 调度 init/接管；新 connection/world 主线程任务须先统一 takeover cleanup（停预览/释 GPU/清 phase/pending，不清订阅），使旧 cleanup no-op 后仍收敛；重复 connect/load 不得重复 reset 投影/发 C2S/清理；cleanup 清 `clientChainEventBus` pending；advance 与 gate 共享 monitor，禁 check 后裸写、禁反向 lifecycle 入口；inactive 丢弃不做 dispatcher rejection warn；不跨 lifecycle 重试
- 客户端断线/世界卸载的 GL 资源释放（`ChainPreviewMeshCache` 等）必须经 `ClientMainThreadDispatcher`，禁在 Netty IO 线程直接释放
- 玩家生命周期清理（退出/重生/切维度/克隆/单人退主菜单）统一经 `ChainStateService.cleanupPlayerState`；服务端停止须先同步完成玩家清理再关闭 dispatcher
- listener 替换交接须在订阅切换完成后重新捕获 Authority（勿仅 seed 可能未更新的 current），覆盖 COW 事件快照窗口
- common Packet/Proxy 方法描述符与字节码禁 client/LWJGL 引用（签名用 common `INetHandler`）
- 向既有固定帧追加玩家偏好时必须保留旧前缀并按精确 payload 长度区分 legacy/extended；旧帧取明确安全默认，未知版本/code、截断和尾随整包拒绝。服务端先原子写 accepted 再 ACK，客户端只按 ACK 投影，禁止保存即乐观改变预览
- 守 I4/I7；详情：`../诊断层/reviews/REVIEW-20260531-issue234-单人退出世界闪退.md`、`../诊断层/reviews/REVIEW-20260531-线程边界同类错误排查.md`、`errors/ERROR-20260710-network-unbounded-backpressure.md`、`errors/ERROR-20260710-config-listener-cow-handoff.md`、决策 `决策/client-connection-identity.md`

### 破坏事件缺失命中面时须显式桥接

- 不得把不携带 sideHit 的破坏事件占位 face 当成真实命中面，也不得用实时视线冒充用户点击表面；在前置左键事件按玩家记录维度、坐标、face 纯值，并由匹配破坏一次性消费。
- 方块面的外法线要转换为朝方块内部的 opposite；缺失、非法、坐标/维度失配必须消费失效并回退同次冻结 look，避免 stale pending 污染下一方块。
- 预览 identity 必须包含最终 concrete face；同 origin 换面也要换 generation。松键、模式变化与生命周期清理必须清 pending。
- 守 I1/I4/I7；详情：`errors/ERROR-20260721-tunnel-direction-hit-face.md`；决策：`决策/tunnel-direction-source.md`

## 构建与依赖环境

- 外部 1.7.10 mod 进 RFG dev runtime 优先依赖 `dev` classifier 或 MCP 变体，禁用无后缀发布 jar（保留 SRG 命名致运行时 `NoSuchMethodError: func_...`）
- 编译通过不能覆盖运行态命名问题；外部 mod 发布 jar 升级后至少跑一次对应 run task（`runClient21`/`runServer25`）
- JitPack 依赖放行必须按发布通道核验，不能机械要求所有仓库都有 Gradle module metadata。Qz-UILib 的 JitPack 组合发布通道以 Build API 身份、canonical POM/main/实际 `dev`/`sources` 及校验和、clean 显式 `:dev` consumer 为证据，`.module=404` 是预期；只有普通 Maven GMM 通道才要求已承诺的 `.module=200` 与变体身份。GitHub Release assets、Maven Local、`www`/query 旁路或非权威镜像不能替代；活动配置禁旧 group/`flatDir` fallback，GTNH Maven 非前置，已发布 tag 不移动
- JitPack 连续失败须拆分 runner 外部 DNS、wrapper 文件 mode、消费者坐标与 CDN 边缘缓存四条链：跨多个域的 `Temporary failure in name resolution` 且每次推进深度不同，优先归为 runner 可达性；origin 已有制品而 canonical 边缘陈旧 404 时按边缘分歧记录，不得以 `www`/query 绕过；构建成功也不自动证明每个边缘已收敛
- tag 前必须由只读 clean runner 在同一 SHA 串行通过 workspace setup、test、check、build；tag 后再独立核验 tag 指向、Release 正文与 assets。branch CI、JitPack 制品矩阵和 Release 结果三者不能互相替代
- 不要并行多个 Gradle 构建；`GRADLE_USER_HOME` 须指向纯 ASCII 路径
- OpenCode 子 agent 统一走 `qz-gradle-opencode/v1`；禁止直接 wrapper、自造后台进程或强杀，超时/孤儿保留锁并升级人工处置
- 详情：`errors/ERROR-20260609-qz-uilib-dev-runtime-deobf.md`、`errors/ERROR-20260713-opencode-gradle-terminal-hang.md`、`errors/ERROR-20260717-jitpack-build-dns-and-coordinate.md`

## 边沿输入与跨轮次电平保持

- 真实按键 listener 只产生物理边沿；若产品允许持续电平跨多个自然结束的 round，必须在旧 round 精确终态后用受限 deferred level-refresh 显式建立新 round，不能等待不存在的第二次上升沿，也不能复活旧 CLOSING/FINISHED round
- 新 round 必须保持 `RoundStart(new nonce) → fresh key=true` 顺序；fresh key 仍走通用按键 packet 与服务端主线程 bridge，禁止从 S2C callback/lifecycle monitor 发 C2S，禁止给状态机增加 `IDLE→PLANNING` 捷径
- 松键、CLOSING 中快速重按、配置关闭、生命周期复位、round 拒绝/orphan、非 FINISHED CLOSE 任一出现即单调取消自动重武装资格；release gate 优先于 natural rearm
- 守 I4/I7/I10；详情：`errors/ERROR-20260716-auto-tool-continuous-rearm.md`

## 协议活跃态与关闭态隔离

- 协议状态必须逐态映射关闭语义；`FROZEN` 等稳定活跃态不得以“非 OPEN”条件折叠为 `CLOSING`
- phase/event 表达“确保已冻结”时必须幂等覆盖未请求、同一请求 in-flight/settled 和服务端已冻结；不得重复分配 action sequence，也不得吞掉首次必要请求
- 回归须同时断言无第二同义 intent、无 `RESTORE/CLOSE`、无 protocol-orphan，并保留真实 `CLOSING` 的新动作安全门
- 守 I4/I10；详情：`errors/ERROR-20260716-auto-tool-frozen-closing-collapse.md`、决策 `决策/auto-tool-swap-server-authority.md`

## 库存事务的新鲜度与角色租约分层

- 当前请求的 TOCTOU 门必须 exact 比较服务端尚未证明的完整内容 fingerprint；跨 round 所有权只比较 stable role，禁止用同一个 full-content hash 同时承担新鲜度与租约，否则合法 count/damage/energy/NBT 变化会永久阻断恢复
- 客户端回显不得重复证明服务端 pending/current 已 exact 比较的同一事实；TAKEOVER 由服务端 pending anchor 对当前 anchor 证明未漂移后，客户端滞后 anchor echo 不再提供额外安全性。候选 exact、ledger role、槽冲突与库存上下文仍须独立保留
- RESTORE 必须先核验 endpoint/round/sequence、ledger 槽位、当前双槽与 intent exact，再核验 ledger role；交换当前真实栈，禁止用旧 snapshot 回写
- 空原 anchor 表示“没有需追回的原物”，不是“该槽永久只能为空”；借用工具原槽被掉落物占用时，应在 exact 新鲜度与活动工具 role 门后原子交换当前双槽。该例外不得扩展到非空原 anchor
- role 不兼容时须显式走可审计的 ABANDON；ABANDON 只接受 canonical control fingerprint，并在零库存读写/同步下清 ledger 到 FINISHED。拒绝、身份不匹配或 transport 失败不得伪造成功
- 详情：`errors/ERROR-20260716-auto-tool-restore-lease-content.md`、决策 `决策/auto-tool-swap-server-authority.md`

## 规划拓扑与执行瞬时资源分层

- planner admission 必须按顶层 mode 分流：CHAIN 在 PlanStarted 主线程冻结“主手 + 背包全部工具 + 空手”能力并集，matcher 无能力即断链；AREA 不按工具能力删目标，只按空间与同块/矿石等子模式结构宽进。不得把任一策略外推到全部采掘模式
- worker 禁读实时 `player.inventory` 或当前主手；CHAIN 只能读取冻结 ItemStack 副本，执行中库存变化不得回写规划拓扑。同块、矿石、原木、TileEntity 纯值身份和对象组结构规则仍由各自 candidate/matcher 保留，AREA 宽进不得退化为无差别几何扫描
- 同一执行资源阈值应集中为纯值策略并由主手短路、候选、服务端写前门和执行器共用，禁止散落魔法数字形成剩余 1 点时的分歧
- 主线程执行门必须逐目标按当前真实玩家、工具、世界、脚底与耐久复验；拒绝或破坏返回 false 只消费该目标并继续。需要等待替代工具时，以独立接替协议控制队列消费，不在 worker 提前删目标
- 范围右键执行同样逐目标读取当前手持，并先过 `World.canMineBlock` 与 `EntityPlayer.canPlayerEdit`；只调用携带目标坐标的 `activateBlockOrUseItem` 以保留 Forge 事件/cancellation。禁止在目标调用返回 false 后退到无坐标 `tryUseItem`，避免作用于准星或空气；失败只跳当前目标
- 直调 `activateBlockOrUseItem` 绕过原版服务端入包处理器的库存后置步骤，必须在 `finally` 重新读取交互后的真实当前槽，只清数量 `<=0` 的栈，不能盲清调用前引用而丢失合法容器替换；归一后标脏，并在当前 `openContainer` 非空时通过正常 listener 调用 `detectAndSendChanges()`。执行器不得设置 `isChangingQuantityOnly=true` 抑制当前玩家槽包；原版 NetHandler 在抑制通用 listener 后另有显式槽包补偿，不能只复制抑制半段。后置异常须独立记录并 fail-closed，不得回滚已发生的交互、恢复零栈、遮蔽主交互异常或阻断后续目标
- 守 I1/I10；详情：`errors/ERROR-20260718-auto-tool-empty-hand-priority.md`；决策：`决策/auto-tool-swap-server-authority.md`

### 未声明 harvestTool 的工具使用稳定 Item API

- 显式 harvestTool 等级始终由 Forge 终裁，不得 fallback 绕过；仅 null harvestTool 且材质仍要求工具时，直接调用 Minecraft owner 上的稳定 `Item.canHarvestBlock(Block, ItemStack)`。
- 不得按 TiC 或其它模组类名维护工具白名单，也不得为资格识别 import/link 对端类型、`Class.forName`、解析成员或扫描方法；Item 虚调用异常 fail-closed。
- 候选资格硬门只保留 canHarvest 与统一耐久储备；`getDigSpeed` 可作为候选事实或排序输入，但不得单独拒绝低效率、可收获工具，其 `RuntimeException/LinkageError` 只令 effective=false，不得污染槽位或完整库存快照。CHAIN 冻结能力复用通用 Item API，AREA planner 不调用工具 API。
- 守 I6；详情：`errors/ERROR-20260721-tconstruct-null-harvest-tool.md`；决策：`决策/auto-tool-swap-server-authority.md`

## 执行等待门必须先于队列消费

- 任何需要异步补齐执行资源的门都必须建立在 `targets.peek()` 与 `poll()` 之间并显式区分四态：WAIT 不消费，STOP 不消费并走会话级协作取消，SKIP_TARGET 只 poll 精确队首并记录 consumed/skipped、绝不到达 `canExecute/execute`，PROCEED 才进入执行器。
- 工具接替不得复用普通 SWAP、建立新 round 或拆分三槽写；同 round pending 使用独立 `takeoverRequestId`，请求发布即烧号且永不回滚，已有 ledger 以单次引用轮转保持可逆。只有原 anchor 为空的合法精确 DECLINE 可形成内部 DECLINED，结算本身零库存读写，poll 前仍须重验空手、库存安全与服务端采掘权威
- APPLIED 不是采掘授权，执行桥继续 poll 前必须重验新主手。请求发送失败、deadline、目标/执行身份漂移、写前库存/候选/ledger 拒绝和目标实时权威失败都只退休精确 request 并 SKIP_TARGET；下一目标重新读取库存并取得新 request ID。旧号、未来号、同号改 payload 及发行 `r+1` 后的旧 `r` exact cache 必须在库存/同步/诊断副作用前拒绝
- mutation 正常返回后，完整库存 publication 与 ActionResult confirm 必须独立可重试：每 round 只保留一个 exact pending，重试重新发送完整 window 0 和同一结果，禁止重放双槽交换或三槽轮转。只有 ActionResult sender 正常返回后 ordinary 才推进 sequence、takeover 才提交 gate 终态；`SYNC_FAILED` 不得清 pending 或启动客户端布局观察
- committed publication pending 不得被 deadline、发送/目标漂移、release、IDLE 或普通 STOP 抢占；Coordinator 必须保留 issued ownership 并返回 WAIT。CLOSE/RESTORE/ABANDON 只可退休尚未 committed 的等待门；断线、重生、切维度、服务停止与真实 watchdog 等硬 lifecycle 才直接销毁记录且不跨生命周期恢复
- 普通静默请求使用固定 cadence immutable retry，准备/恢复/关闭类事务另有硬 deadline；TAKEOVER 与普通 in-flight identity 必须隔离，新请求只能替换未提交旧 ownership，已提交/布局验证中只排队 latest，A→B→C 的迟到 A/B 结果不得清 C 或普通动作
- 合法空手 DECLINE 后若需消除逐目标网络等待，只能租赁“稳定候选资格”，不得缓存每目标采掘权威：单项 round 租约须绑定 endpoint/round/generation、block id + 完整 metadata、空锚点槽与 0..35 逐槽 exact identity；命中仍逐目标实时 `canHarvest`，任一身份变化先清旧租约再重新执行真实候选优先协商
- 非 GT 普通 `CHAIN/AREA/INTERACT/SPECIAL` 的执行预算必须统计所有实际 poll，而非只统计成功执行；只要消费过目标就发布一次推进事件，允许 `executedThisTick=0`。WAIT/STOP 即使出现在本 tick 已消费之后也要先完成推进尾处理；规划未完成的瞬时空队列不得提前 FINISHED。GT 线缆的单 tick 原子分支与旧取消例外必须独立保持
- CHAIN 连通遍历必须把冻结能力 matcher 拒绝解释为拓扑断链。`CHAIN_LOGGING` 的 candidate=false 与 matcher=false 都不入队、不增加 confirmed、不生成邻居；只有 matcher=true 才继续预算化扩展。执行期实时拒绝仍只跳当前已规划目标，不能反向删改 topology
- 守 I1/I4/I10；详情：`errors/ERROR-20260716-auto-tool-takeover-poll-loss.md`、`errors/ERROR-20260718-auto-tool-empty-hand-priority.md`、`errors/ERROR-20260718-auto-tool-close-planning-publication.md`、`errors/ERROR-20260718-empty-hand-takeover-throughput.md`、`errors/ERROR-20260724-auto-tool-stop-session-amplification.md`、`errors/ERROR-20260725-auto-tool-request-sync-recovery.md`

## 派生预览必须租赁不可变 seed

- SWAP/TAKEOVER/RESTORE 先收到成功 ActionResult，再在原版完整库存的目标布局首次可见时刷新预览；`SYNC_FAILED` 或 APPLIED 回包本身都不触发
- 预览首次捕获完整 `BlockSeedSnapshot` 并绑定 world/lifecycle identity；工具布局刷新复用同一 block/meta/tile seed，不得从已破坏 origin 回读 air
- seed 租约结束时同步清除动作去重身份；旧 generation worker 只能协作终止，不能写入新预览
- 守 I2/I7；详情：`errors/ERROR-20260718-auto-tool-empty-hand-priority.md`

## 预备态目标快照与库存事务必须绑定

- 依赖准星目标的候选扫描必须在 light 阶段固化值身份，并由 FULL 复用；禁在库存扫描中二次读取 `objectMouseOver`，避免目标与候选发生 TOCTOU。
- 目标身份只包含决定候选能力的 block id + metadata；坐标变化不得制造事务，采样异常不得伪装成 ABSENT。短暂无目标须使用固定 tick 防抖，并锁定 1/2 tick 边界测试。
- 方块 ID 与 metadata 校验域必须以字段真实类型与 sentinel 合同为准，不得从 vanilla、历史 ID 扩展器或存储实现推导更窄上限。当前存在目标 block ID 覆盖 `1..Integer.MAX_VALUE`，metadata 覆盖 `0..Integer.MAX_VALUE`，不得 mask/truncate；固定覆盖 16、24902、65535、16777216、`Integer.MAX_VALUE`、负值与 block ID 0。Java int 不得用 `Integer.MAX_VALUE + 1` 伪造越界，parser 以十进制字符串 `2147483648` 覆盖超界。
- `registry@meta` 的 SINGLE/SET/WILDCARD、同 registry union 与跨组 intersection 必须使用完整非负 int domain；禁止恢复位移 mask 或 `meta<16` 热路径。值域放宽不取消每成员 1024-byte、每组/总成员和 payload 上限，Picker 只接收 `getSubBlocks` 实际暴露的非负 metadata，不枚举整个 int 域。
- latest-target-wins 只能覆盖尚未执行的匹配资格；已提交 SWAP/RESTORE 必须完成。已有 ledger 先 RESTORE 清账，再对最终目标 FULL，禁覆盖 expectation 或发送第二个普通 SWAP。
- FROZEN、GUI/re-anchor、release、配置关闭和 lifecycle 的硬收口优先于目标重匹配；进入 FROZEN 即清除预备态资格。
- 非生命周期的瞬时采样失败不得调用 lifecycle reset 或清客户端 round/ledger；松键事实仍须推进关闭义务，待后续安全采样完成 RESTORE/CLOSE。只有真实连接/世界生命周期入口可硬复位。
- 守 I4/I7/I10；详情：`errors/ERROR-20260716-auto-tool-preparing-latest-target.md`、`errors/ERROR-20260717-auto-tool-extended-block-id-release-reset.md`、决策 `决策/auto-tool-swap-server-authority.md`。

## 连锁遍历器 origin 处理语义

- 遍历器 `seed()` 对 origin 的处理必须按触发模式分化：破坏后事件触发（FloodFill 系 CHAIN/AREA/BoxScan/SectionClear，origin 已被原版破坏，排除正确）vs 取消破坏事件触发（GT 线缆 SPECIAL_REPLACE 走 `LeftClickObserved` 预取消原版破坏，origin 仍在世界，必须入 frontier）
- 新增遍历器时先确认触发模式属于哪一类，再写 `seed()` 的 origin 处理；语义内化进各专属遍历器，不上升到接口开关（双执行路径违背单一执行原则）
- 修触发链路任一层时，沿链路上下游排查语义是否对齐（触发入口 → planner seed → step → consumer）
- 详情：`errors/ERROR-20260706-cable-origin-not-replaced.md`、决策 `决策/chain-origin-inclusion-semantics.md`

## 属性变更型操作的跨 tick 中间态安全

- 「替换/改造」类操作（改变方块属性而非破坏）若目标系统（GT 电力网、IC2、AE）对中间态敏感，必须走单 tick 原子路径，禁套用流式 `maxBreakPerTick` + 节流戳控速
- 单 tick 原子路径必须配预校验放行门：上限阈值（防卡 tick）+ 资源充足（防半途断料），任一失败提示玩家 + 不放行，不能赌运气
- 通用执行控速（`ChainExecutionEventBridge.consumeContext` 非 GT 分支）只对"语义中性"的破坏安全；新增 `ChainActionExecutor` 若属属性变更型，必须显式评估中间态合法性，必要时覆盖 `shouldWaitForPlannerCompletion=true` 走原子路径
