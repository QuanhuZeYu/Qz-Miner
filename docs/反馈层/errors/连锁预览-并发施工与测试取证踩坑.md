# 连锁预览并发施工 · 编译中间态与测试取证踩坑（2026-09-13）

多 owner 共享同一工作区并行施工时踩到的坑，供后续轮次参考。

## 1. 他人中间态会反复让 compileJava / compileTestJava 变红

- 现象：锁脚本 build/test 报错的文件不是自己的，连续几轮换不同 owner 的文件。
- 处置：先看报错文件的 LastWriteTime 与当前内容，再判断是否仍在演进；多数错误 owner 会在数分钟内自修，直接重试即可。
- 反例：本轮 session-core 曾为 shader / render / config 三个 owner 的中间态各升级一次，属于无效噪音——先查文件时间再决定是否上报。

## 2. Gradle `--tests` 过滤器必须带通配符

- 现象：`gradlew test --tests club.heiqi.qz_miner.chain.client.ChainPreview` 直接 BUILD FAILED，报
  `No tests found for given includes`（编译已绿也会失败）。
- 原因：`--tests` 按完整类名匹配，短前缀不是前缀匹配。
- 正确写法：`--tests "club.heiqi.qz_miner.chain.client.ChainPreview*"`（锁脚本 `test --filter` 原样透传）。

## 3. 测试结果快照会被他人的 test 运行覆盖

- Gradle `:test` 每次运行都会重写 `build/test-results/test/*.xml`。
- 取证必须在自己的运行结束后立即读取；否则已被后续 owner 的结果覆盖，只能重跑。

## 4. double 配置字段传给 float 形参需要显式 cast

- `Config.clientPreviewFadeRefreshDistance / clientPreviewLodMinAlpha / clientPreviewAlpha*` 是 double，
  传给 float 构造参数时 javac 报"从 double 转换到 float 可能会有损失"（编译错误，不是警告）。
- 统一在 `ChainPreviewVisualSettings.fromConfig()` 内显式 `(float)` 收窄。

## 5. 门控临时补丁的删除条件要写在代码现场

- B0.3 的 `publicationAwaitingConsumption` 消费门控是临时补丁：
  删除条件 = B4.1 增量路径上线且差分测试通过后，随该次替换一并删除；已写在 `ChainPreviewRenderCache` 字段注释处。
