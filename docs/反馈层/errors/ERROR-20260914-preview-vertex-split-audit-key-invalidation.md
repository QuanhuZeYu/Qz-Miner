# ERROR-20260914 顶点按面分裂会静默废掉「按索引建键」的网格审计

## 现象

T51 方案 A（顶点身份从「位置」升级为「(位置, 面)」，让外扩方向语义生效）落地后：

- 几何与四元组结构**完全正常**（quad 数一个没变，闭合体、绕向、体积全对）；
- 但 `VerifyMeshAudit.openEdge` 从 **0** 变成 **192**（single 形状），`nonManifoldEdge` /
  `inconsistentWinding` 同步失真；
- 进一步连锁：`VerifyMeshReferenceModel.compare` 的 `duplicateVertexPosition` 在每个
  顶点上都报一次，11 个依赖参考模型的测试集体变红。

几何没坏，红的是**审计方法**。

## 根因

审计用**顶点索引对**当边的键：

```java
long key = (min(from,to) << 32) | max(from,to);
state[0]++;                          // 该边被几个 quad 使用
state[1] += from < to ? 1 : -1;      // 绕向一致性
```

「闭合流形」的判据是「每条边恰被 2 个 quad 使用、且两次绕向相反」。这个判据成立的前提是
**同一条几何边在相邻面上复用同一个顶点索引**。

顶点按面分裂后，这个前提消失了：同一条几何边在相邻两个面上各持一个顶点，用的是**不同索引**。
于是每个索引对只被「看到」一次 ⇒ 每条边都被判成开放边。审计不是报错，而是在用旧身份口径
**正确地度量了一个已经不存在的关系**。

同一层的第二个受害者是参考模型的 `duplicateVertexPosition`：它把「同位置多顶点」当错误，
而方案 A 恰恰**要求**同位置多顶点。判据与被测契约方向相反，必然全红。

## 教训

**审计/契约的键必须与被审计对象的身份处于同一抽象层。** 身份口径变更时，键、去重口径、
不变量判据要**一起**迁移；只改实现不改审计，会得到一批"看起来像几何回归"的假红灯，
而它比真回归更危险——因为它会诱导人回退正确的改动。

## 修法

- 边键从「索引对」迁到「位置对」：先做 `位置 -> 稳定 id` 映射（同一位置恒得同一 id），
  再用 id 对建边、用 id 序判绕向。语义与原实现逐条等价，只是键换了抽象层。
- 参考模型的顶点键升级为 `位置 + "|" + face`，比较口径改为
  **每位置顶点数一致** + **同位置 aux 语义一致**（后者顺带独立复核了构建侧的
  `normalizeAppearOrderByPosition()`）。
- 方向流契约从「钉住当前全零缺口」改为**几何自洽**断言：逐 quad 用顶点绕向算外法线，
  它必须等于该 quad 四个顶点的 `aDirection` 值。方向写反、同面不同向、跨面共享都会立刻红灯。

## 代价与配套

顶点数 ×2.625（single 64→168、line_100 1648→3336、scattered_4096 262144→688128），
quad 数不变。孤立方块包络由 64 顶点/块升到 168 顶点/块，容量上界守卫与测试堆同步调整（2g）。

## 独立验算

金值来源：工作站 `temp/chain-preview/verify/cp_verify_split_model.py`（复用 T7 独立 Python 几何
重建，按 `CUBOID_QUAD_INDICES` 展开每个 quad 的角点后按 `(位置, 面)` 去重）。11 个形状的
顶点数与 Java 实测**逐个吻合**，且自检「split 顶点的位置投影 == 原位置数」「quad 数不变」全部通过。
