# Issue 诊断支持政策

## 决策

玩家提交 Issue 时，唯一必要信息是用自己的话描述“遇到了什么问题”和实际表现。图片、视频、触发方式、版本与日志均为可选信息，不以完整环境、复现矩阵或日志包作为受理前置条件。

维护者负责根据症状路由到现有日志和诊断 marker。初步证据不足时，应结合已知症状每次提出一个具体补充请求，而不是让玩家执行通用测试或一次性收集全部材料。内部症状路由以 `docs/控制律层/稳定命令.md` 为准。

## 原则

- **描述优先**：先理解玩家观察到的行为，不因缺少技术材料拒绝问题。
- **维护者路由**：由维护者判断客户端、服务端、GregTech 或 native 日志中哪一项与症状相关。
- **按需单点追问**：只追问当前判断所缺的一个关键信息，并说明需要查看的时段或 marker。
- **隐私最小化**：优先接收相关片段；不默认索取全量日志、环境清单、NBT 或与问题无关的信息。

## 边界

本政策不减少项目自身的自动化、CI 与维护者验证责任，也不承诺仅凭一句描述一定能完成根因定位。现有日志出现具体盲区时，再围绕该 Issue 评估最小诊断补强，不预先把采集成本转嫁给所有玩家。
