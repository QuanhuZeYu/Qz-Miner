## 当前状态

- 当前 5.2 候选架构以 `ChainPlayerState` 作为服务端玩家连锁权威状态入口。
- `ChainSession` 只描述单次连锁请求与运行态，不再承担玩家资产级掉落缓存职责。
- 玩家级掉落缓冲位于 `src/main/java/club/heiqi/qz_miner/chain/state/ChainPlayerDropBuffer.java`，由 `ChainPlayerState` 持有。
- `ChainRuntimeState` 只负责单次会话的规划订阅、遍历队列、待破坏队列、执行节流和匹配计数。
- `ChainSession` 仍持有 `ChainRuntimeState`，但外部核心链路优先通过 `ChainSession` 委托方法访问运行态。
- 掉落释放与会话生命周期已解耦，会话结束不再依赖旧 `session` 保留到掉落释放完成。
- 玩家退出、重生、切维度、克隆、单人退主菜单等生命周期事件统一通过 `ChainStateService.cleanupPlayerState(...)` 处理。
- GT 线缆替换模式的锁定 MetaTileId 会在会话替换、会话清理和玩家生命周期清理时同步移除。
- GT 线缆能力经字符串类名与精确声明成员反射解析完整 profile，不静态链接 GT 类型、不扫描公开成员；任一替换必需成员缺失即整体降级。替换复用同一管线基座，建立 meta/base 双向绑定并同时恢复两侧连接位，刷新使用 `issueTextureUpdate`、`issueTileUpdate` 与 `causeCableUpdate`，失败时回滚旧 meta、ID 与连接。`IRedstoneTileEntity.issueBlockUpdate` 仅承担红石/邻居通知，不属于两代线缆替换 profile。旧线缆由主线程执行器返还背包，满包时进入玩家级掉落缓冲。
- world-tick 释放路径四级降级链：玩家当前位置 → 重生/出生点 → 已记忆兜底坐标 → 连续失败 100 tick 后告警 discard。spawn 处 `EntityItem.forceSpawn=true` 绕 `chunkExists` 早 return，降级路径可能触发主线程同步 chunk 加载（本征代价，可接受）。失败计数挂 `ChainPlayerState.dropReleaseConsecutiveFailures`，`clearRuntimeState` 清零。
- 掉落释放先从玩家级缓冲取出快照；若实体生成失败或抛出运行时异常，未生成的掉落会回填到缓冲，避免释放失败导致吞物品。
- `CHAIN / AREA` 的规划线程只标记规划完成，不得在观察到空队列时直接把执行状态切到 `IDLE` 或清理 session；最终结束统一由服务端主线程 `ChainExecutionEventBridge` 消费完队列后 publish `ExecutionFinished`，状态机 T7 收口判断。
- 当前并行线程仍允许异步读取世界，这只是现状，不表示线程模型已经彻底安全。
- 世界写入、真实方块破坏、掉落实体生成仍在主线程逻辑中完成。
- 客户端预览会在断线和客户端世界卸载时经 `ClientMainThreadDispatcher` 停止并行预览任务，并释放 `ChainPreviewMeshCache` 持有的 GPU 资源。
- `SimpleNetworkWrapper` 的服务端入包与客户端状态同步已统一通过 `ServerMainThreadDispatcher` / `ClientMainThreadDispatcher` 收口后再触碰主线程语义状态。
- Forge 连接握手由 `MyMod` 中全仓唯一 `@NetworkCheckHandler` 委托 `QzMinerNetworkVersionPolicy`：
  仅接受完整合法的 5.2 family，忽略 patch/qualifier，排除 5.0/5.1/5.10/畸形版本；远端 map 缺精确
  `qz_miner` 时 CLIENT/SERVER 都只放行 mod-list 检查，不保证无 Mod channel 或业务安全。5.2.0
  同时冻结 17 个 discriminator/Side、现有 wire/protocol/ordinal/code/mask 与 23-path schema，
  不提供跨 minor fallback；真实 mixed-patch/missing 运行态仍为 **INCOMPLETE**。
- LootGames 扫雷兼容层已改为反射可选加载，构建时不再要求编译期引入 LootGames dev 依赖；兼容层不能调用会扫描 LootGames 方块类公开方法的反射 API，服务端应按稳定棋盘布局解析 master 与炸弹坐标，避免客户端专属签名类加载。
- 可选模组反射统一通过 `ClassNameCompatSupport` 与 `ReflectiveMemberSupport` 处理，类探测不触发静态初始化，成员解析必须吞掉 `LinkageError` / `SecurityException` 并以兼容能力不可用降级。
- 同一 jar 同时包含 GTNH 2.8 legacy 与 2.9 adapter 矿石时运 mixin；plugin 按目标类字节码中的方法名和 descriptor 精确选择，不能仅凭类存在启用。两代均直接拦截 `fortune > 3`；自然矿字段按 2.9 `isNatural`、2.8 `mNatural` 反射解析，玩家放置矿共享同一配置语义。
- GTNH 2.9 beta 中 `BaseMetaPipeEntity.issueClientUpdate()` 已移除，GT 线缆替换后客户端同步使用 `issueTileUpdate()`，同时保留 `issueTextureUpdate()` 与 `GregTechAPI.causeCableUpdate(...)`；不再从错误 owner `gregtech.api.interfaces.tileentity.IGregTechTileEntity` 要求 `issueBlockUpdate()`。
- `BoxScanTraverser` 当前已经改为增量壳扫，预算化路径会把空队列推进、壳层坐标扫描、候选 poll、匹配检查和 consumer 提交全部计入 `ParallelTickControl` 工作预算。
- 并行 Tick 框架层已使用 `ParallelTaskResult` 区分继续、让出、自然完成和安全终止；`ParallelTickTask.run(...)` 通过 `ParallelTickControl` 观察窗口、取消请求与单片工作预算。
- 并行 Tick 单片工作预算可配置：服务端阶段读取 `general.parallelTickServerWorkBudgetUnits`，默认 `640`；客户端阶段读取 `client.parallelTickClientWorkBudgetUnits`，默认 `640`；执行器创建每片 `ParallelWorkBudget` 时会把配置值夹到至少 `1`。
- planning 候选事务由 `ChainSearchContext` 持有的唯一 `PlanningCandidateWorkBudget` 计费：只有本次读取精确得到 `Blocks.air` 时享受固定 1024:1，同一 context 的余数跨 step、slice 与 tick 保存；第 1024 个空气必须先取得 1 个正预算再提交，不足时坐标游标、visited、frontier、queue、confirmed 与余数均不推进。自然完成不补收尾余数，也不跨 context、玩家、round 或预览共享。
- 每个候选在世界读取前仍先检查取消与 `shouldYield()`；空气提交后不调用 candidate filter、matcher 或 consumer，也不入 frontier。非空气候选、重复坐标、frontier 轮转、shell/slice 切换、方向解析、matcher 与 consumer 继续正常收费，因此整次遍历总成本不等于简单的 `air/1024`。
- `ParallelTickExecutor.unregister(...)` 的常规语义是请求取消并唤醒 worker，任务从注册列表移除发生在 worker 返回 `COMPLETED`、`TERMINATED` 或 `FAILED` 后；`Future.cancel(true)` 只保留在执行器最终关闭兜底路径。
- `ParallelTickExecutor.endStage(...)` 仍是主线程屏障，必须等待所有 active worker 停到安全边界；进入新分片前需要确认窗口仍打开、阶段匹配、tick 未过期。
- 服务端规划与客户端预览任务已经先适配协作式取消：取消、旧会话或旧预览 generation 不应再向旧队列/旧预览状态写入结果。
- 连锁遍历层的稳定接口是 `BudgetedChainTraverser` 与 `TraversalStepResult`；旧 `ChainTraverser.step(context, int maxNodes, ...)` 兼容接口和 `ChainTraverser.java` 已删除，任务层通过 `ChainTraversalSupport` 直接调用预算化 traverser。
- `ChainPlanningRuntime`、`ChainModeDefinition`、`ChainSubModeDefinition` 与 `ChainSubModeRegistry` 直接传递 `BudgetedChainTraverser`，新增主模式或子模式 traverser 必须实现预算化分片接口。
- `FloodFillTraverser`、`GregTechCableTraverser`、`LoggingFloodFillTraverser`、`BoxScanTraverser`、`TunnelBoxScanTraverser`、`SectionClearTraverser` 与 `CuboidScanTraverser` 已接入预算化状态机；frontier 搬运、邻居生成、节点 poll、候选检查、坐标扫描、空队列/空切片/空壳层推进和 consumer 提交均可跨分片恢复。框选 traverser 使用单坐标游标，不预展开体积，并在预算不足时事务性保留当前位置。
- `LoggingFloodFillTraverser` 不再在构造器里一次性构造完整 offset 列表，伐木 origin 邻居生成也从 `seed(...)` 下沉到首次预算化分片逐步推进。
- `FloodFillTraverser` 与 `GregTechCableTraverser` 的 `seed(...)` 只初始化 visited 与可恢复游标；首次世界/candidate 探测在带 `ParallelTickControl` 的 `step(...)` 内完成。GT origin 仍参与替换，connected-side 捕获、完整规划完成门与主线程单 tick 原子执行合同不变。
- `CHAIN_LOGGING` 与其它 CHAIN 洪泛一致采用能力断链：candidate=false 或最终采掘 matcher=false 都会清当前目标，不入执行队列、不增加 confirmed，也不生成后续邻居；只有 candidate/matcher 均接受的节点才按预算化邻居游标继续扩展。
- `TunnelBoxScanTraverser.seed(...)` 只初始化状态并标记 origin 已访问，首个 3x3 切片下沉到预算化分片内扫描，避免 seed 绕过预算协议。
- 配置权威为 `config/qz_miner.yaml`（UILib 配置运行时 + Schema）；当前 schema 为 23 字段，运行时读取面仍是 `Config` 的 22 个静态字段。YAML 路径只要是文件即取得权威，零长度按结构化空 MAP 使用全部 schema 默认且不读取/退役 cfg。启动先经 `RawYamlPreflight` 做原始 NodeType 检查，再用共用 `ConfigSemanticValidator` 严格校验；语法/raw/语义坏 YAML 必须备份成功后删除、默认重建并复验。旧 `qz_miner.cfg` 由 `LegacyCfgImporter` 一次性导入；成功迁移与失败默认恢复均须先退役 cfg，再统一发布 `yamlFile`、manager、current 与 22 个 Config 字段；任一提交前失败零发布。默认单一源为 `QzMinerConfigDefaults`。
- 已验证快照是 Authority 的只读派生载荷；current 是 `epoch + ValidatedSnapshot` 的不可变提交包装，epoch 跨测试 reset 也不回退。`commitManager` 先构造可能失败的 committed wrapper，再发布 static/global。client/server 各有无锁 latest-wins 单消费者 mailbox，`processedEpoch` 为已处理水位（stale 未 publication 也推进；publication 失败不推进）；publication 在锁外且开始前复核 current identity；调度失败保留 pending，关闭后 queued task no-op，不依赖 FIFO。分侧发布仍为 client 经 `ClientMainThreadDispatcher`，general 仅在服务端主线程（集成服经 `ServerMainThreadDispatcher`；远程客户端不写 general）；`serverStarting` 只发布 current snapshot。
- `/qzminer config list|get|set|reload` 是 permission level 4 的服务端配置入口，只暴露显式 `general.*` scalar 白名单。`set` 必须经 `openDraft → setDraft → save`，`reload` 复用 UILib 严格加载；成功提交后 `ServerConfigHotApplyService` 按 epoch 幂等发布 general、toolswap policy 和在线玩家 accepted 裁剪/同步，失败不推进 Authority 或运行态。
- Qz-UILib 为 `required-after:qz_uilib@[4.6.0,)` 硬依赖；权威远端来源为 JitPack，活动配置使用标准坐标 `com.github.QuanhuZeYu:Qz-UILib:4.6.3:dev`，并已移除 Maven Local/`flatDir` 旧 group fallback，GTNH Maven 非发布前置。4.6.3 的正式 Release、JitPack `ok` tag/commit 身份与 canonical POM 已确认，Miner 以显式 `:dev` 解析和本仓构建验证实际消费；完整发布放行仍按 POM/main/`dev`/`sources` 内容与校验和及 clean consumer 分层记录。JitPack 组合发布通道的 `.module=404` 是预期，不套用普通 Maven Gradle Module Metadata 规则。GTNH 支持基线与预期 GregTech 版本由 `gradle/gtnh-baselines.json` 统一定义，默认出包 manifest 仍由 `gradle.properties` 唯一决定；branch CI 为每项基线建立独立 clean runner并精确断言解析版本，tag workflow 在任何 checkout、构建或 Release 副作用前强制要求同一 SHA 的 branch push CI 成功。tag 后仍需另行核验 Release 与 assets。
- 结构化 `client.objectGroups` schema 为 `{id,modes LIST<CHOICE>,members LIST<STRING>}`，members 使用 UILib 4.6.0 `LIST_MEMBERS` 管理选择器：外层常驻已配置/无效/重复摘要与管理入口，raw 默认折叠为高级编辑；portal 宽高受视口约束，搜索固定在顶部，当前规则/搜索结果按 3:5 目标动态分区，overlay 打开期间约束焦点并在关闭后恢复。成员按稳定 ID 单项替换，新增选择追加为新成员；删除由成员行发起并二次确认，不再只走 raw。重复 registry 只提示、不自动合并；parser 保留各输入成员的顺序与独立 canonical/wire 边界，同 registry 的运行时语义在冻结快照中取并集；旧 aggregate codec 的同 registry 归一行为仅保留为兼容接口，不代表当前 UI。合法但当前未枚举的 selector 显示 canonical；malformed 在常规 UI 只显示通用说明、不泄露原始文本，高级 raw 仍无损保留。Picker 包严格 client-only，每屏在客户端主线程枚举全部合法 `Block.blockRegistry` 方块并固化搜索/图标快照，不访问 world、worker 或 NEI；空气、火、传送门等技术块也会出现。正常 ItemBlock variant 仅来自 `getSubBlocks` 实际暴露的非负 int metadata，不再限 0..15；无 ItemBlock 方块保留逻辑 meta 0 variant，ItemStack 始终为 null 并显示占位图，不伪造物品身份，也不推断 `getSubBlocks` 未暴露的状态。配置页提供“全部状态 / 指定状态”中文 presentation。selector 的单值、集合和通配覆盖 `0..Integer.MAX_VALUE`，每成员仍受 1024-byte、每组 128 成员与总成员/载荷上限。缺失 modes 归一为空，默认提供三个空 modes 的 vanilla 组。`ObjectGroupMode.java` 固定 7 个稳定 id/bit；跨组仅共享 mode 且完整 metadata 域相交时多路径拒绝。C2S wire protocol v2、revision 快照绑定、latest-wins、主线程收口、ACK/pending 与 S2C 固定 25 字节机制不变。

- 自动工具换位的唯一 physical ledger owner 是服务端主线程上的 `AutoToolSwapServerBatchService`。它直接交换或轮转 `InventoryPlayer.mainInventory[0..35]` 的当前真实 `ItemStack` 引用：首次借用为二槽交换，连续接替为 `A<-D,C<-A,D<-C`，segment/final restore 只交换已分类的当前布局。mutation 正常返回即提交；抛错只按 pre/post/unknown image 分类且永不盲目重放。`AutoToolSwapRoundService` 已收敛为零库存 wire projection/control，客户端、coordinator 与五态机均不持有第二 physical ledger。
- local session 绑定玩家 UUID、endpoint/world identity、dimension、generation、`serverRoundId`（含合法值 `0`）、anchor slot、owner epoch 与冻结 policy epoch。服务器从自身 `CommittedSnapshot` 读取 `autoToolSwapEnabled` 和 `autoToolPrioritySelectors`，活动 session 不受 reload 改写；远程客户端不上传 selector/enable。每目标由 `MinecraftAutoToolSwapCandidateSource` 重读 live block/meta、当前手和 `0..35`，按 `ToolHarvestEligibility`、`ToolCandidateOrder` 与槽号稳定排序，并在 mutation 后继续由 `ChainHarvestRules.canHarvest` 终裁。
- 普通 `CHAIN/AREA` 在 `targets.peek()` 后、`poll()` 前调用 local `prepareTarget`，正常值只有 `PROCEED/SKIP_TARGET/STOP`。production 热路不发送逐目标自动工具请求、不产生网络 `WAIT`；`PROCEED/SKIP_TARGET` 才 poll，后者不调用执行器，STOP 保留队首并进入恢复屏障。GT 线缆 SPECIAL 与 INTERACT 不接入。
- 一个 ordinary batch 内允许多次 mutation，但只把玩家的 publication gate 标脏；每玩家每 server tick 完整 window 0 publication 全局最多尝试一次。`CONTINUE` 在 server tick END flush；terminal batch 先 final restore，再重新 `markDirty()` 并通过 `sendContainerToPlayer(...)` 发布最终布局，最后才允许 `ExecutionFinished/LifecycleCleanup/IDLE`。同步失败不回滚或重放 mutation，只留下无 mutation 权限的 visibility tombstone 供下一 tick 重试，也不无限阻塞 cleanup。
- natural finish、松键、PlanCancelled、ordinary STOP、watchdog、logout、respawn、切维度、clone 与 server stop 都在 projection、registry、状态或 endpoint 清理前经过幂等 local finalizer。非 forced event 必须匹配当前 owner 的 round/generation，forced lifecycle 按玩家收口；clone 同时尝试 old/new endpoint。未知第三布局、endpoint 不可用与 mutation 未应用均显式分类并 fail closed，不搬运、合并或覆盖外部物品，也不伪报恢复成功。
- 自动工具 v4 保留五包、discriminator `10..14`、动作/状态/结果 code 与普通 `actionSequence`。client 激活后直接发送 `FREEZE`，不构造 physical SWAP；takeover packet、独立 request ID、客户端库存扫描与跨 minor fallback 已删除。
- 非 GT 普通 `CHAIN/AREA/INTERACT/SPECIAL` 执行循环仍以本 tick 实际 `poll()` 数而非成功数约束 `maxBreakPerTick`；成功、`canExecute=false`、`execute=false` 与 `SKIP_TARGET` 共用同一处理预算。只要消费过目标就发布一次 `ExecutionAdvanced`，零成功时 `executedThisTick=0`，仅成功数大于 0 才设置 50ms 节流；同 tick 已消费后再遇到 STOP 时先发布真实推进，再过 restore/publication 屏障收口。GT 线缆仍走等待 planner、预校验和单 tick 原子分支。
- `INTERACT` 四个子模式统一声明仓内宽泛 `RIGHT_CLICK`，服务端既观察 Forge `RIGHT_CLICK_BLOCK`，也观察 `RIGHT_CLICK_AIR`。非液体 BLOCK 保留 event 目标坐标；AIR 只从当前不含液体射线取得语义目标；液体模式的 BLOCK/AIR 都从包含液体射线取得目标。ray miss 或非 BLOCK 不发布，AIR 的占位坐标不进入 seed。四模式的 server/preview 仍使用预算化 `BoxScanTraverser` 扫描完整立方范围，主模式显示默认立方尺寸。base 按冻结 block/完整 metadata/tile token，liquid 按冻结流体身份与 live source，crop 按全部可靠已识别作物，fertilize 只按可靠 live IMMATURE；候选拒绝只跳当前坐标，不中止后续盒扫。
- base/crop/fertilize 的 `TargetRevalidatingBlockInteractActionExecutor` 在服务端主线程逐目标复用世界保护与编辑权限门，再按不可变 request 重建 live matcher；liquid 执行器同样在权限门后重验同种 source，并只要求调用时存在当前非空手持栈，不预判物品类型或流体接收能力。方块执行逐目标重读当前手持，只调用携带目标坐标的 Forge 交互入口。通用与液体交互都在 `finally` 经 `InteractionInventorySupport` 重新读取交互后的真实当前槽：仅把数量 `<=0` 的栈清为 null，保留物品逻辑替换出的合法容器或其它栈；随后标脏库存，保持正常 container listener（不设置 `isChangingQuantityOnly`），并在当前 `openContainer` 非空时直接调用 `detectAndSendChanges()` 同步。单目标无动作、拒绝、返回 false、异常、耗尽或同步失败只按本目标 false 结算，执行队列继续消费。
- 客户端普通预览仍为当前 origin 租赁首次捕获的完整 `BlockSeedSnapshot` 与 world identity。ARMED 未触发时准星可自由重选；`PlayerControllerMP.onPlayerDestroyBlock(...)=true` 且坐标命中当前 frozen origin 是本地租约线性化点，在异步 phase 尚未投影的窗口立即锁住该 origin。PLANNING/RUNNING/FINISHING 或本地租约任一成立都不采样新准星；观察到本轮同/更新 generation 终态、松键、禁用、停止或 lifecycle 后释放。local mutation 没有逐动作 verified-layout effect，预览作为 observer 可在批内滞后且不能阻塞服务端 poll budget。完整 reset 同步清 seed/动作去重/本地租约，旧 generation worker 不得污染新预览。
- 框选预览独立于逐方块预览：客户端只接受当前连接内 revision 单调的 `PacketCuboidSelectionSync`，两点齐全时以 `[min,max+1]` 常驻绘制固定 6 面/12 边 AABB，并完整恢复 GL 状态。服务端按 accepted `chainMaxBlocks` 原子接受或拒绝两点；规划时把 bounds 冻结进 request/session，重选只影响下一 round。连接、世界与玩家生命周期清理两侧选区；真实鼠标取消、GL 与 client/dedicated 运行态仍为 **INCOMPLETE**。
- 正常破坏入口在服务端主线程、origin 被移除前把 block、完整 metadata 与 seed TileEntity 捕获为冻结值；服务端右键入口先把 Forge action 解析为语义目标，再在原物品动作生效前的最后存活窗口冻结同一组三项事实。两条路径经观测事件、`PlanStarted`、`BlockSeedSnapshot` 与 `ChainSearchContext` 传播，规划不得回读动作后的 seed；仅左键兼容路径仍可在主线程走 resolver。普通 same-block worker 不持有或读取 seed TileEntity，候选侧仍按现状从只读 World 获取 TileEntity 后立即纯值化，因此这不是全 worker 世界快照化。身份矩阵对 block/metadata 先精确比较，`ABSENT` 仅匹配 `ABSENT`，`PRESENT` 要求 strategy/type/key 全同，任一 `UNRESOLVED` fail-closed；未知模组按 runtime type name 工作。GT 线缆特殊模式与客户端预览的既有专用 TileEntity 兼容字段保持不变。
- 规划桥还会把同一 `BlockSeedSnapshot` 的 block、完整非负 int metadata 与 `TileIdentityToken` 写入不可变 `ChainRequest`，由 `ChainSession` 只读透传给执行期；旧构造器使用 null/0/`UNRESOLVED` 安全默认。request/session 不持有 live World、TileEntity、NBT 或 Class，执行期世界变化不能反向改写 seed。
- 范围交互作物能力已接入用户子模式：`CropGrowthState` 以 MATURE/IMMATURE/UNKNOWN 表达 vanilla、IC2/GT CropCard 与 EFR 作物成熟度，`INTERACT_CROP` 接受全部可靠已识别作物，`INTERACT_FERTILIZE_IMMATURE_CROP` 每次读取 live block/meta/tile 且只接受可靠 IMMATURE。UNKNOWN、反射调用异常均 fail-closed；兼容层不调用施肥或收获。
- `INTERACT_LIQUID_SOURCE` 使用 `ChainLiquidRules`/`LiquidSourceBlockMatcher` 冻结 seed 流体名，vanilla 只接受 metadata 0，Forge 候选逐目标以 `IFluidBlock.canDrain` 终裁同种可排液 source；不调用 `drain`。`InteractionRayTrace` 是不含 client-only 类型的 side-neutral helper：服务端入口、液体客户端预览与执行期精确门复用 Item 1.7.10 的 current/prev pose、remote eye offset 和 `func_147447_a(..., includeLiquids, false, false)` 数学，各调用方传当前侧实际 block reach。其它客户端预览继续使用 `Minecraft.objectMouseOver`。
- `LiquidSourceInteractActionExecutor` 复用通用交互的世界保护与编辑权限门，逐目标重验 request seed 与同种 live source，再把当前非空手持栈交给 Item 自己决定是否处理；不引用容器注册表或动态容器接口，也不按 filled/full/未知物品预判。执行时 `TargetInteractionPose` 把虚拟 eye 放入目标块内靠近冻结 face，`ServerPlayerPoseTransaction` 临时统一 current/prev/last 坐标、current/prev yaw/pitch 与平移后的 bounding box；共享 liquid-inclusive ray 首命中精确目标后，才发布 Forge `RIGHT_CLICK_AIR` 并调用 `tryUseItem`。姿态在库存同步前恢复，不发送虚拟位置包。对象组 bit、mask、配置 schema 与 packet framing 均未改变。
- `AREA_TUNNEL` 的具体方向在主线程冻结为 Minecraft 六面编号。`LOOK_DIRECTION` 沿视线绝对值最大轴；`HIT_FACE` 在左键事件记录不持有 World/Event 的一次性命中纯值，并仅由随后同维度、同坐标破坏消费其 opposite face。缺失、非法或失配立即清 pending 并回退同次冻结 look；松键、模式/子模式切换和玩家清理同样清 pending。非隧道路径不读取或消费该状态。客户端预览把 concrete face 纳入同 origin/world 的 generation identity，方向变化会重启预览，旧 worker 不能回写新方向结果。
- 自动工具候选不再维护 TiC 或其它模组类白名单：目标未声明 harvestTool、材质仍要求工具时，直接经 Minecraft 稳定 `Item.canHarvestBlock(Block, ItemStack)` 虚调用取得结论，调用异常 fail-closed；显式 harvestTool 仍完全由 Forge 等级语义终裁。候选资格硬门只有 `canHarvest` 与至少 2 点剩余耐久；`getDigSpeed` 只是可选事实，其 `RuntimeException/LinkageError` 仅降级为 effective=false，不污染该槽或完整库存快照。CHAIN 冻结能力复用同一资格入口，AREA planner 不调用工具 API，执行期仍由服务端主线程实时权威终裁。
## 当前模式边界

- 主模式：`CHAIN / AREA / INTERACT / SPECIAL`。
- 掉落相关问题主要影响 `CHAIN` 与 `AREA`，因为它们共用 `BlockHarvestActionExecutor` 和 `HarvestDropsEvent` 聚合链路。
- `SPECIAL` 当前是异构子模式容器，不应假设其完全共享 `CHAIN / AREA` 的执行闭环。

## 当前已知重点风险

- 并行规划线程仍会直接触发部分权威状态变更，后续若继续出现时序类问题，应优先检查 `planner -> ChainStateService` 的调用链。
- 自定义 `PlayerDisconnectEvent` 虽已在 `PlayerManager` 内部收口到服务端主线程，但 `QzEvents` 仍是同步分发；后续若新增该事件监听器，仍需自行处理线程边界。
- 玩家级掉落缓冲虽然已经与会话解耦，但跨生命周期兜底释放仍依赖 Minecraft 1.7.10 的重生点与世界上下文 API。
- 全项目系统性风险审查已完成，严重和高风险条目详见 `docs/诊断层/reviews/REVIEW-20260528-代码框架设计风险排查.md`。
