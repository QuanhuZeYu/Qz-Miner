本文件记录项目的稳定架构边界、核心数据流和模块职责约束。

## 当前状态

- 当前 5.0 架构以 `ChainPlayerState` 作为服务端玩家连锁权威状态入口。
- `ChainSession` 只描述单次连锁请求与运行态，不再承担玩家资产级掉落缓存职责。
- 玩家级掉落缓冲位于 `src/main/java/club/heiqi/qz_miner/chain/state/ChainPlayerDropBuffer.java`，由 `ChainPlayerState` 持有。
- `ChainRuntimeState` 只负责单次会话的规划订阅、遍历队列、待破坏队列、执行节流和匹配计数。
- `ChainSession` 仍持有 `ChainRuntimeState`，但外部核心链路优先通过 `ChainSession` 委托方法访问运行态。
- 掉落释放与会话生命周期已解耦，会话结束不再依赖旧 `session` 保留到掉落释放完成。
- 玩家退出、重生、切维度、克隆、单人退主菜单等生命周期事件统一通过 `ChainStateService.cleanupPlayerState(...)` 处理。
- GT 线缆替换模式的锁定 MetaTileId 会在会话替换、会话清理和玩家生命周期清理时同步移除。
- GT 线缆能力经字符串类名与精确声明成员反射解析完整 profile，不静态链接 GT 类型、不扫描公开成员；任一必需成员缺失即整体降级。替换复用同一管线基座，建立 meta/base 双向绑定并同时恢复两侧连接位，刷新失败回滚旧 meta、ID 与连接。旧线缆由主线程执行器返还背包，满包时进入玩家级掉落缓冲。
- world-tick 释放路径四级降级链：玩家当前位置 → 重生/出生点 → 已记忆兜底坐标 → 连续失败 100 tick 后告警 discard。spawn 处 `EntityItem.forceSpawn=true` 绕 `chunkExists` 早 return，降级路径可能触发主线程同步 chunk 加载（本征代价，可接受）。失败计数挂 `ChainPlayerState.dropReleaseConsecutiveFailures`，`clearRuntimeState` 清零。
- 掉落释放先从玩家级缓冲取出快照；若实体生成失败或抛出运行时异常，未生成的掉落会回填到缓冲，避免释放失败导致吞物品。
- `CHAIN / AREA` 的规划线程只标记规划完成，不得在观察到空队列时直接把执行状态切到 `IDLE` 或清理 session；最终结束统一由服务端主线程 `ChainExecutionEventBridge` 消费完队列后 publish `ExecutionFinished`，状态机 T7 收口判断。
- 当前并行线程仍允许异步读取世界，这只是现状，不表示线程模型已经彻底安全。
- 世界写入、真实方块破坏、掉落实体生成仍在主线程逻辑中完成。
- 客户端预览会在断线和客户端世界卸载时经 `ClientMainThreadDispatcher` 停止并行预览任务，并释放 `ChainPreviewMeshCache` 持有的 GPU 资源。
- `SimpleNetworkWrapper` 的服务端入包与客户端状态同步已统一通过 `ServerMainThreadDispatcher` / `ClientMainThreadDispatcher` 收口后再触碰主线程语义状态。
- LootGames 扫雷兼容层已改为反射可选加载，构建时不再要求编译期引入 LootGames dev 依赖；兼容层不能调用会扫描 LootGames 方块类公开方法的反射 API，服务端应按稳定棋盘布局解析 master 与炸弹坐标，避免客户端专属签名类加载。
- 可选模组反射统一通过 `ClassNameCompatSupport` 与 `ReflectiveMemberSupport` 处理，类探测不触发静态初始化，成员解析必须吞掉 `LinkageError` / `SecurityException` 并以兼容能力不可用降级。
- 同一 jar 同时包含 GTNH 2.8 legacy 与 2.9 adapter 矿石时运 mixin；plugin 按目标类字节码中的方法名和 descriptor 精确选择，不能仅凭类存在启用。两代均直接拦截 `fortune > 3`；自然矿字段按 2.9 `isNatural`、2.8 `mNatural` 反射解析，玩家放置矿共享同一配置语义。
- GTNH 2.9 beta 中 `BaseMetaPipeEntity.issueClientUpdate()` 已移除，GT 线缆替换后客户端同步使用 `issueTileUpdate()`，同时保留 `issueTextureUpdate()`、`issueBlockUpdate()` 与 `GregTechAPI.causeCableUpdate(...)`。
- `BoxScanTraverser` 当前已经改为增量壳扫，预算化路径会把空队列推进、壳层坐标扫描、候选 poll、匹配检查和 consumer 提交全部计入 `ParallelTickControl` 工作预算。
- 并行 Tick 框架层已使用 `ParallelTaskResult` 区分继续、让出、自然完成和安全终止；`ParallelTickTask.run(...)` 通过 `ParallelTickControl` 观察窗口、取消请求与单片工作预算。
- 并行 Tick 单片工作预算可配置：服务端阶段读取 `general.parallelTickServerWorkBudgetUnits`，默认 `640`；客户端阶段读取 `client.parallelTickClientWorkBudgetUnits`，默认 `640`；执行器创建每片 `ParallelWorkBudget` 时会把配置值夹到至少 `1`。
- `ParallelTickExecutor.unregister(...)` 的常规语义是请求取消并唤醒 worker，任务从注册列表移除发生在 worker 返回 `COMPLETED`、`TERMINATED` 或 `FAILED` 后；`Future.cancel(true)` 只保留在执行器最终关闭兜底路径。
- `ParallelTickExecutor.endStage(...)` 仍是主线程屏障，必须等待所有 active worker 停到安全边界；进入新分片前需要确认窗口仍打开、阶段匹配、tick 未过期。
- 服务端规划与客户端预览任务已经先适配协作式取消：取消、旧会话或旧预览 generation 不应再向旧队列/旧预览状态写入结果。
- 连锁遍历层的稳定接口是 `BudgetedChainTraverser` 与 `TraversalStepResult`；旧 `ChainTraverser.step(context, int maxNodes, ...)` 兼容接口和 `ChainTraverser.java` 已删除，任务层通过 `ChainTraversalSupport` 直接调用预算化 traverser。
- `ChainPlanningRuntime`、`ChainModeDefinition`、`ChainSubModeDefinition` 与 `ChainSubModeRegistry` 直接传递 `BudgetedChainTraverser`，新增主模式或子模式 traverser 必须实现预算化分片接口。
- `FloodFillTraverser`、`GregTechCableTraverser`、`LoggingFloodFillTraverser`、`BoxScanTraverser`、`TunnelBoxScanTraverser` 与 `SectionClearTraverser` 已接入预算化状态机，frontier 搬运、邻居生成、节点 poll、候选检查、坐标扫描、空队列/空切片/空壳层推进和 consumer 提交会消耗 `ParallelTickControl` 工作预算并可跨分片恢复。
- `LoggingFloodFillTraverser` 不再在构造器里一次性构造完整 offset 列表，伐木 origin 邻居生成也从 `seed(...)` 下沉到首次预算化分片逐步推进。
- `TunnelBoxScanTraverser.seed(...)` 只初始化状态并标记 origin 已访问，首个 3x3 切片下沉到预算化分片内扫描，避免 seed 绕过预算协议。
- 配置权威为 `config/qz_miner.yaml`（UILib 配置运行时 + Schema）；运行时读取面仍是 `Config` 静态字段。YAML 路径只要是文件即取得权威，零长度按结构化空 MAP 使用全部 schema 默认且不读取/退役 cfg。启动先经 `RawYamlPreflight` 做原始 NodeType 检查，再用共用 `ConfigSemanticValidator` 严格校验；语法/raw/语义坏 YAML 必须备份成功后删除、默认重建并复验。旧 `qz_miner.cfg` 由 `LegacyCfgImporter` 一次性导入；成功迁移与失败默认恢复均须先退役 cfg，再统一发布 `yamlFile`、manager、current 与 22 个 Config 字段；任一提交前失败零发布。默认单一源为 `QzMinerConfigDefaults`。
- 已验证快照是 Authority 的只读派生载荷；current 是 `epoch + ValidatedSnapshot` 的不可变提交包装，epoch 跨测试 reset 也不回退。`commitManager` 先构造可能失败的 committed wrapper，再发布 static/global。client/server 各有无锁 latest-wins 单消费者 mailbox，`processedEpoch` 为已处理水位（stale 未 publication 也推进；publication 失败不推进）；publication 在锁外且开始前复核 current identity；调度失败保留 pending，关闭后 queued task no-op，不依赖 FIFO。分侧发布仍为 client 经 `ClientMainThreadDispatcher`，general 仅在服务端主线程（集成服经 `ServerMainThreadDispatcher`；远程客户端不写 general）；`serverStarting` 只发布 current snapshot。
- Qz-UILib 为 `required-after:qz_uilib@[4.6.0,)` 硬依赖；权威远端来源为 JitPack，活动配置使用标准坐标 `com.github.QuanhuZeYu:Qz-UILib:4.6.1:dev`，并已移除 Maven Local/`flatDir` 旧 group fallback，GTNH Maven 非发布前置。4.6.1 的 annotated tag、Release/workflow、JitPack API 身份、canonical POM/main/`dev`/`sources` 内容与校验和及 clean 显式 `:dev` consumer 已验证；JitPack 组合发布通道的 `.module=404` 是预期，不套用普通 Maven Gradle Module Metadata 规则。tag 前还须取得候选同 SHA branch CI 的 clean-runner setup/test/check/build 证据，tag 后另行核验 Release 与 assets。
- 结构化 `client.objectGroups` schema 为 `{id,modes LIST<CHOICE>,members LIST<STRING>}`，members 使用 UILib 4.6.0 `LIST_MEMBERS` 管理选择器：外层常驻已配置/无效/重复摘要与管理入口，raw 默认折叠为高级编辑；portal 宽高受视口约束，搜索固定在顶部，当前规则/搜索结果按 3:5 目标动态分区，overlay 打开期间约束焦点并在关闭后恢复。成员按稳定 ID 单项替换，新增选择追加为新成员；删除由成员行发起并二次确认，不再只走 raw。重复 registry 只提示、不自动合并；旧 aggregate codec 的同 registry 归一行为仅保留为兼容接口，不代表当前 UI。合法但当前未枚举的 selector 显示 canonical；malformed 在常规 UI 只显示通用说明、不泄露原始文本，高级 raw 仍无损保留。Picker 包严格 client-only，每屏在客户端主线程枚举全部合法 `Block.blockRegistry` 方块并固化搜索/图标快照，不访问 world、worker 或 NEI；空气、火、传送门等技术块也会出现。正常 ItemBlock variant 仅来自 `getSubBlocks` 实际暴露的 0..15 metadata；无 ItemBlock 方块保留逻辑 meta 0 variant，ItemStack 始终为 null 并显示占位图，不伪造物品身份。配置页提供“全部状态 / 指定状态”中文 presentation。缺失 modes 归一为空，默认提供三个空 modes 的 vanilla 组。`ObjectGroupMode.java` 固定 7 个稳定 id/bit；跨组仅共享 mode 且 selector 区间相交时多路径拒绝。C2S wire protocol v2、revision 快照绑定、latest-wins、主线程收口、ACK/pending 与 S2C 固定 25 字节机制不变。
- 客户端配置页为 `QzMinerConfigGUI`；`ClientConfigChangeListener` 接受 `BATCH_SAVE` 与 `RELOAD`，替换/reset 先关闭旧 mailbox 再精确退订，替换时在订阅锁内 `captureCommittedSnapshot` 重新捕获 Authority 后锁外 dispatch。现有半径 C2S/S2C 与连接 identity 生命周期范式保持不变；对象组确认同样经 `ClientConnectionLifecycle` 主线程 gate。服务端代码不引用 ConfigUI、屏幕桥接壳或 LWJGL；common Packet/Proxy 签名与字节码不含 client/LWJGL。
- 客户端连锁 HUD 在 `ClientProxy.init` 向 Qz-UILib 紧凑 HUD 注册一次并跨断线保留；连接清理只重置客户端投影/预览，不关闭或重复注册 HUD。`QzMinerHudSnapshotProvider` 只发布不可变语义行，不持有 Forge overlay、字体、坐标或格式码渲染职责；common/server 不引用 UILib HUD API。
- 对象组已收口为七个既有子模式的可选筛选扩展，`ChainSubMode` 仅保留原 0-11 ordinal。服务端主线程按当前 submode、seed 和每玩家已接受 ruleset 解析唯一组，冻结为 `ModeExtensionSnapshot` 并贯穿 request/session/context；热路径按 registry 查 16-bit metadata mask。candidate filter 使用 `Q OR X`；最终 matcher 先按 Q 短路，五个采掘模式仅对 X 分支执行 `ChainHarvestRules.canPlanHarvest`，只判断目标与采掘能力、不因瞬时耐久储备丢弃待执行目标；主线程 `BlockHarvestActionExecutor` 仍以 `ChainHarvestRules.canHarvest` 执行完整耐久门。`INTERACT_BASE` 仅要求 X 命中，`INTERACT_CROP` 仅要求 X 命中且目标非 null/air/liquid。空扩展与非支持模式均保持原判定实例；reload 不改变已启动任务。客户端预览用服务端已确认 ruleset 和同一工厂路径解析，pending 回退 Q。
- 自动工具换位的唯一库存写权位于服务端主线程：`AutoToolSwapRoundService` 经 `MinecraftAutoToolSwapInventoryPort` 交换 `InventoryPlayer.mainInventory[0..35]` 的当前真实 `ItemStack` 引用、标记库存变更并调用原版容器差异同步；客户端只读库存、选择候选并发送 Qz-Miner intent，不执行 `windowClick`。协议 v3 保留候选 exact fingerprint 新鲜度门与 stable-role ledger；TAKEOVER 以 pending/current 服务端 anchor exact 作为锚点未漂移证明，不再重复要求客户端 anchor echo exact。普通 SWAP/RESTORE 的双槽 exact 门不变。无旧 ledger 做双槽交换；有旧 ledger 单次执行 `A<-D,C<-A,D<-C` 并滚动为唯一 ledger，最终 RESTORE 仍只交换当前真实内容，不回滚动态字段。
- 自动工具 `serverRoundId` 由服务端激活 round 时分配并随 `ChainEvent` 不可变传播；`AutoToolSwapRoundPhaseProjectionBridge` 只按事件自带 round 关联专用阶段投影，通用 `PacketChainPhaseSnapshot` 不承担工具事务关联。客户端 cycle、协议身份、动作等待、库存期望、关闭原因和重传统一由 `AutoToolSwapClientReducer` 写入；`AutoToolSwapClientAdapter` 只采样 Minecraft 事实、执行不可变 effect 与网络 I/O，`AutoToolSwapClientProtocolValidator` 无持久状态。GUI 打开或热栏 re-anchor 优先触发 RESTORE；松键、配置关闭或专用 IDLE 执行 RESTORE 后 CLOSE。原 anchor 非空且 role 租约不兼容时，客户端以 ledger 双槽和 canonical control fingerprint 发送显式 `ABANDON`；原 anchor 为空时，candidate 后来被掉落物占用仍以 RESTORE 原子交换当前双槽，使借用工具回原槽、占位物进入主手。服务端只在 endpoint/round/sequence/state/ledger/槽位均匹配时处理，ABANDON 保持零库存访问。自然 IDLE 的成功 ABANDON 与成功 CLOSE 一样可保留受限 deferred rearm；其他路径进入 IDLE 或 WAIT_RELEASE。通信、身份拒绝或生命周期异常不伪造成功，也不跨连接盲目恢复库存。
- 首块成功前的准星身份由 `ToolSwapTargetIdentity` 固化为 `ABSENT` 或 `blockId + metadata`，合法域为正 24-bit block ID 与完整 16-bit metadata（0..65535），不截断且不含坐标、World、Block 或 TileEntity/NBT。`ToolSwapMinecraftFacade` 在 light 阶段只采样一次目标，普通 FULL 复用该快照；异常采样整次失败，不伪装成 ABSENT。`AutoToolSwapClientReducer` 独占 latest/matched/连续 ABSENT 水位：有效目标变化立即触发，连续两个 END tick ABSENT 才确认丢失；已有 ledger 必须完成 RESTORE 后才为最终目标 FULL，已提交 SWAP/RESTORE 不取消，FROZEN 清除预备态重匹配资格。
- 普通 CHAIN/AREA 执行在 `targets.peek()` 后、`poll()` 前调用 `AutoToolSwapTakeoverCoordinator`。剩余耐久不足时建立最多 10 tick 且短于 watchdog 的等待门并下发包含 generation、目标坐标与 block id/meta 的第四个自动工具 S2C；WAIT/STOP 均不消费队首，只有 APPLIED 才继续 poll。TAKEOVER 仍重验 endpoint/protocol/round/sequence/pending/deadline、FROZEN/keyDown、服务端 anchor、候选、ledger、槽位和库存上下文；每个进入结算的动作只输出一条固定 reason 诊断。客户端 S2C callback 只登记事实，下一 ClientTick 才按服务端目标 FULL 采样并发送 TAKEOVER/DECLINE；GT 线缆 SPECIAL 原子分支不接入。`client.autoToolTakeoverEnabled` 默认 true，热关闭只阻止新 TAKEOVER。
## 当前模式边界

- 主模式：`CHAIN / AREA / INTERACT / SPECIAL`。
- 掉落相关问题主要影响 `CHAIN` 与 `AREA`，因为它们共用 `BlockHarvestActionExecutor` 和 `HarvestDropsEvent` 聚合链路。
- `SPECIAL` 当前是异构子模式容器，不应假设其完全共享 `CHAIN / AREA` 的执行闭环。

## 当前已知重点风险

- 并行规划线程仍会直接触发部分权威状态变更，后续若继续出现时序类问题，应优先检查 `planner -> ChainStateService` 的调用链。
- 自定义 `PlayerDisconnectEvent` 虽已在 `PlayerManager` 内部收口到服务端主线程，但 `QzEvents` 仍是同步分发；后续若新增该事件监听器，仍需自行处理线程边界。
- 玩家级掉落缓冲虽然已经与会话解耦，但跨生命周期兜底释放仍依赖 Minecraft 1.7.10 的重生点与世界上下文 API。
- 全项目系统性风险审查已完成，严重和高风险条目详见 `docs/诊断层/reviews/REVIEW-20260528-代码框架设计风险排查.md`。
