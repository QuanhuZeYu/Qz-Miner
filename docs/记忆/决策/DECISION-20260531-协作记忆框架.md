# 决策：采用分层 AI 协作记忆框架

## 背景

原有协作文档主要依赖 `AGENTS.md` 和 `docs/AI记忆文档.md`。随着项目推进，单一核心文档会同时承载导航、当前状态、长期事实和历史结论，既容易膨胀，也不利于多人或多 Agent 协作。

## 候选方案

1. 继续维持单一核心记忆文档，只通过更严格的书写纪律控制膨胀。
2. 引入外部数据库、向量记忆或独立记忆服务。
3. 在仓库内建立分层记忆框架，将规则、当前态、长期事实和决策记录拆开维护。

## 最终选择

选择方案 3，在仓库内建立分层记忆框架。

## 选择原因

- 保持纯仓库内实现，便于版本控制和共同维护。
- 不依赖外部基础设施，适合当前项目阶段。
- 小文件、单职责更适合按需读取和更新。
- 分离当前态与长期事实后，更不容易把核心文档写膨胀。

## 影响范围

- 后续协作入口应优先读取 `docs/记忆/README.md`。
- `docs/AI记忆文档.md` 降级为总导航入口。
- 当前态、长期事实和决策记录不再堆进单一文档。
- `AGENTS.md` 的规则层需要与新框架保持同步，避免规则层与文档层口径分裂。

## 后续注意事项

- 当项目结构、命令或边界稳定下来后，及时写回 `docs/记忆/长期事实/`。
- 当前阶段变化写回 `docs/记忆/当前态/`。
- 关键取舍写回 `docs/记忆/决策/`。
