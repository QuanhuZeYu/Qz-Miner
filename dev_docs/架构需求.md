# Qz-Miner 架构需求文档

## 1. 重构目标

### 1.1 主要目标
- **代码可维护性**：提高代码的可读性和可维护性
- **扩展性**：支持新功能的快速添加
- **性能优化**：解决已知的性能问题
- **模块化**：清晰的模块划分和职责分离

### 1.2 具体目标
1. 解决事件总线卡顿问题
2. 重构异步设计，提高稳定性
3. 改进配置系统，支持游戏内可视化调整
4. 优化搜索算法，提高性能
5. 改进错误处理和日志系统

## 2. 架构原则

### 2.1 设计原则
- **单一职责原则**：每个类只负责一个功能
- **开闭原则**：对扩展开放，对修改关闭
- **依赖倒置原则**：依赖抽象而非具体实现
- **接口隔离原则**：使用专门的接口

### 2.2 代码组织原则
- **按功能分组**：相关的类放在同一个包中
- **清晰的层次结构**：核心逻辑、客户端、网络分离
- **最小化依赖**：减少模块间的耦合

## 4. 核心设计模式

### 4.1 策略模式（搜索算法）
```java
interface SearchStrategy {
    List<Vector3i> search(Vector3i start, SearchContext context);
    void cancel();
}

class BFSSearchStrategy implements SearchStrategy { ... }
class DFSSearchStrategy implements SearchStrategy { ... }
class OreSearchStrategy implements SearchStrategy { ... }
```

### 4.2 工厂模式（操作器创建）
```java
interface OperatorFactory {
    ChainOperator createOperator(OperatorType type, PlayerState state);
}

class DefaultOperatorFactory implements OperatorFactory { ... }
```

### 4.3 观察者模式（事件处理）
```java
interface ChainEventListener {
    void onChainStart(ChainStartEvent event);
    void onChainEnd(ChainEndEvent event);
    void onModeChange(ModeChangeEvent event);
}
```

### 4.4 状态模式（模式管理）
```java
interface ChainState {
    void handleKeyPress(PlayerState state);
    void handleBlockBreak(PlayerState state);
    void handleModeSwitch(PlayerState state);
}

class InactiveState implements ChainState { ... }
class ActiveState implements ChainState { ... }
class PausedState implements ChainState { ... }
```

## 5. 数据流设计

### 5.1 连锁流程
```
玩家按键 → 输入处理 → 状态检查 → 模式选择 → 
搜索算法 → 位置队列 → 操作执行 → 结果反馈
```

### 5.2 数据同步流程
```
客户端配置 → 网络发送 → 服务端接收 → 
状态更新 → 网络广播 → 客户端更新
```
