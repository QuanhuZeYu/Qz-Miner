# Qz-Miner 5.3.1

> **已定档 `5.3.1`（小版本 / patch）**。依据：Miner 的版本 family 就是网络兼容 family——
> `QzMinerNetworkVersionPolicy.isCompatibleFamily` 只接受完整的 `5.3.x` family（`QzMinerNetworkVersionPolicyTest`
> 明确拒绝 `5.10.0` 等其它 family），且 5.3.x 全组合互通；本轮**不改协议/wire**，留在 5.3 family 才能保持
> `5.3.0` ↔ `5.3.1` 联机互通。若进 `5.4.x`，会无故切断 5.3.0 与新版的互通——`5.4.x` 留给协议/wire 变化时使用。
>
> 随定稿同步：开发默认版本由 `5.3.0-dev` 升为 **`5.3.1-dev`**（`build.gradle.kts` 第 7 行，沿用历史口径
> 5.2.0-dev → 5.2.1-dev → 5.3.0-dev 的「dev 默认 = 当前开发版本」约定）；打 tag 与发布走 UILib 同一套流程
> （分支 CI 绿 → 回填 CI 证据 → annotated tag → tag 触发的发布 workflow），
> 本文件已回填分支 CI 证据，可随 tag 直接作为 Release notes。

## 兼容性

- 网络协议不变：仍是 5.3 冻结族（17 个 packet discriminator/Side、20-path 配置 schema、wire 合同 53）。
- 依赖边界：编译与运行时 Qz-UILib 最低 **4.9.1**（`[4.9.1,5.0.0)`）——公开 HUD 编辑契约
  （`HudEditTarget` / `HudEditService` / `ChatActionService`）自 4.9.1 起提供，4.9.0 不满足；
  4.9.1 相对 4.9.0 为纯增量且 UILib 远端混用面为 `[4.9.0,4.10.0)`，故 4.9.1 与 4.9.0 可双端混用，
  但**本 Mod 的运行下界以 4.9.1 为准**；GTNH 基线为单值 `2.9.0-beta-3`。
- 同版本内容漂移（本轮新增风险，需集成方按 sha 核对）：运行期下界仍为 `[4.9.1,5.0.0)`，但本轮引用的
  `HudLayoutStore` / `HudLayoutPersistence` 只存在于**本轮交接的 4.9.1 构建件**（sha256 `1AB9DFE7…`）；
  同版本号的旧 4.9.1 件（`7E0A8EF2…` / `57BAB4C2…` 等）不含这些类，混用会在类加载期 `NoClassDefFoundError`。
  制品契约守卫（`QzUiLibArtifactContractTest`）只按 `mcmod.info` 版本区间判定，**识别不了这种同版本内容漂移**，
  故集成/发布必须以本文件与 `dependencies.gradle` 注释的 sha256 为准。
- 同 jar 兼容：运行期兼容范围含 `2.9.0-beta-2` 与 `2.9.0-beta-3`，依据是源码对 GTNH 侧组件零静态链接
  + 双基线 `compileJava`/`compileTestJava` 实证（2026-09-11）；真机运行态未验证。
- 兼容承诺的表达方式变化：同 jar 兼容不再由 CI 矩阵分别构建证明；`2.8.4` 仍不在承诺内
  （上游 POM 缺陷结论不变，见 `ERROR-20260817`）。双基线证据改为人工流程：临时切换
  `setGtnhVersion` 编译后按原始字节恢复并校验 sha256（`-P` 覆盖通道已失效）。
