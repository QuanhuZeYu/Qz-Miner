# Qz-Miner 5.3.1

> 版本号待发布定档：文件名 `5.3.1` 为候选编号（HEAD 当前位于 `5.3.0` 标签提交，本轮不改协议/wire，patch 语义成立）。
> 若用户定档为 `5.4.0` 等其它版本，重命名本文件即可；本文只描述改动与验证边界，不表示发布状态。

## 更新

- 依赖基线对齐 Qz-UILib：GTNH 基线升至 `2.9.0-beta-3`，真源收敛为 `dependencies.gradle` 的
  `elytraModpackVersion { setGtnhVersion("2.9.0-beta-3") }` 单值声明；`gradle.properties` 不再声明
  `elytra.manifest.*`。实测运行期组件版本：GT5 5.09.54.133、GTNHLib 0.11.46、Hodgepodge 2.7.196、
  NewHorizonsCoreMod 2.9.61、Et-Futurum-Requiem 2.6.58-GTNH、lwjgl3ify 3.0.31、Angelica 2.2.10。
- 多基线 CI 机制退役：删除 `gradle/gtnh-baselines.json`、`scripts/verify-gtnh-baselines.ps1` 与
  `build.gradle.kts` 的 `verifyGtnhBaseline` 任务；`branch-ci.yml` 收敛为单基线作业（保留 JDK 列表、
  `setupCIWorkspace`、`test`/`check`/`build`、`Tags.VERSION` 生成源与主 jar 常量池校验），
  `release-tags.yml` 删除基线解析并去掉全部 `-Pelytra.manifest.version` / `-Pqz.gtnh.*`。
- 接入 Qz-UILib 4.9.0 dev 制品（`libs/qz_uilib-4.9.0-dev.jar`），`@Mod` 依赖范围改为
  `required-after:qz_uilib@[4.9.0,5.0.0)`。
- HUD 接入迁移到 Qz-UILib 4.9 虚拟窗口契约：`ui.hud.api` 删除 `CompactHud` / `HudSnapshotProvider` /
  `HudLine` / `HudSnapshot` / `HudSpan` / `HudTone` / `TextHud`，新增 `HudWindowFactory` /
  `HudLayoutService` / `HudToolbarService` 等。Miner 侧删除 `QzMinerHudSnapshotProvider`，改为
  `QzMinerHudModel`（业务状态 → 不可变语义模型）+ `QzMinerHudWindow implements HudWindowFactory`
  （`Signal<Model>` + `SceneRuntime.forEach` keyed 列表 + `SceneChromeTokens.HUD_TEXT_*`）
  + `QzMinerHudTicker`（`ClientTickEvent.END` 冲刷）；注册仍是 `ClientProxy.init` 单点
  `ClientHudService.register(HudSpec("qz_miner:chain-status", HudAnchor.TOP_LEFT), factory)`，断线不重注册、不 close。
  - 功能等价点：内容集合与行序不变；锚点仍为左上角、窗口显隐仍由 UILib 宿主负责；空模型 → 内容根零尺寸 →
    宿主整窗隐藏（对齐旧 EMPTY 快照）；色调语义 `Tone.{MUTED,INFO,SUCCESS,WARNING}` 映射
    `SceneChromeTokens.HUD_TEXT_*`，HUD 文本不含样式编码。
  - 编译断裂清单与取舍见 `docs/反馈层/errors/ERROR-20260911-uilib-49-hud-api-removal.md`。

## 兼容性

- 网络协议不变：仍是 5.3 冻结族（17 个 packet discriminator/Side、20-path 配置 schema、wire 合同 53）。
- 依赖边界：编译与运行时 Qz-UILib 最低 4.9.0（`[4.9.0,5.0.0)`）；GTNH 基线为单值 `2.9.0-beta-3`。
- 同 jar 兼容：运行期兼容范围含 `2.9.0-beta-2` 与 `2.9.0-beta-3`，依据是源码对 GTNH 侧组件零静态链接
  + 双基线 `compileJava`/`compileTestJava` 实证（2026-09-11）；真机运行态未验证。
- 兼容承诺的表达方式变化：同 jar 兼容不再由 CI 矩阵分别构建证明；`2.8.4` 仍不在承诺内
  （上游 POM 缺陷结论不变，见 `ERROR-20260817`）。双基线证据改为人工流程：临时切换
  `setGtnhVersion` 编译后按原始字节恢复并校验 sha256（`-P` 覆盖通道已失效）。
