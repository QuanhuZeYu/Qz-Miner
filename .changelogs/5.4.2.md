# Qz-Miner 5.4.2

## 更新

- **联机版本判定改用 FML 原生区间（替换 5.4.1 的自造实现）**：5.4.1 用自造解析器 + `@NetworkCheckHandler` 表达「同一 `major.minor` 族互通」；本版改为声明 `@Mod.acceptableRemoteVersions = [X.Y.0-alpha, X.(Y+1).0-alpha)`（`X.Y` = 本构建的 `major.minor`），由构建从制品版本派生为编译期常量，解析与比较交给 FML 的 Maven 版本序实现。自造解析器与 `@NetworkCheckHandler` 一并删除——FML 的 `NetworkModHolder` 里两者互斥：有 handler 时走 `MethodNetworkChecker`，区间对象根本不会被创建，握手与「接受自身版本」自检都会失效。
  - 区间两端写 `-alpha` 的依据：Maven 语义里只有 `alpha` / `beta` / `milestone` / `rc` / `snapshot` 五个已知限定符被判为预发布，且 `alpha` 最小；因此该区间恰好覆盖 X.Y 族（含其预发布与未知限定符），同时把相邻族的最小形态 `X.(Y+1).0-alpha` 挡在上界之外。
  - **语义变化（有意）**：改用 Maven 语义后不再做严格语法校验——`X.Y` 等价于 `X.Y.0` 而被接受，前导零、溢出、Unicode 等形态按该语义解析后参与比较。5.4.1 的自造实现在这些形态上 fail-closed；取舍是复用生态已验证的实现，不再自造并维护一整套边界。
- **启动期自检恢复**：声明区间后，FML 会在启动时用 `acceptVersion` 检查「本 mod 是否接受自身版本」，不接受即报 `appears to reject its own version`——正是 5.4.0 事故缺失的信号。同一条不变量另由 `NetworkVersionRangeTest` 在构建期钉住（区间边界矩阵 + 不得声明 `@NetworkCheckHandler`）。
- **排查陷阱（写进注释与测试）**：FML 启动日志里的「The mod qz_miner accepts its own version」读的是 `acceptableRemoteVersions` 区间，**不经过** `@NetworkCheckHandler`；该属性为空时它退化为「自身版本等于自身」的恒真判断，不能作为放行证据。

## 兼容性与升级动作

- **5.4.1 ↔ 5.4.2 互通**：两版兼容族相同（都由 `major.minor` 决定），可混用——区间判定放行 `5.4.1`，5.4.1 的族判定同样放行 `5.4.2`。
- **5.4.0 仍必须升级**：它拒绝一切远端版本（含同为 5.4.0 的对端），任何一端留在 5.4.0 都联不上机。
- **联机规则**：区间 `[X.Y.0-alpha, X.(Y+1).0-alpha)` 内互通（含 patch / prerelease / build qualifier 差异），区间外 fail-closed。
- **依赖配对不变**：仍要求 Qz-UILib `>=4.11.0,<5.0.0`（`required-after:qz_uilib@[4.11.0,5.0.0)`）。
- **联机边界不变**：不改 packet / Side、wire / protocol 与 schema 范围。
- **升级动作**：客户端与服务端替换为 5.4.2；与 5.4.1 可混用，无需手工改配置或迁移数据。
