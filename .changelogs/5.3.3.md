# Qz-Miner 5.3.3

## 更新

- 新增连锁/爆破的饥饿值消耗配置 `harvestExhaustionPerBlock`（#242）：默认 `0.025` 等于原版每方块消耗，手感与上一版一致；合法区间 `0..40`，`0` 表示关闭。
- 结算只在方块真正被移除后发生：被拒绝、被取消或中途失败的破坏不消耗，创造模式与假玩家不消耗；默认档不产生额外的原版外调用。
- 出厂默认对象组新增「暮色森林极光方块」（`TwilightForest:tile.TFAuroraBrick@*`），修复极光方块无法连锁（#249）：它的 metadata 是位置导出的相位值，此前被同块身份门判为不同类，只能连同相位的竖直列与一侧对角，连不成一片。
- metadata 通配只作用于该方块自身，其它方块的同类判定不放宽；「红石矿石」默认组的模式与成员未变。
- 配置项的本地化文案、`/qzminer config set` 白名单与使用文档同步补齐。

## 兼容性与升级动作

- **依赖不变**：仍要求 Qz-UILib `>=4.10.0,<5.0.0`（`required-after:qz_uilib@[4.10.0,5.0.0)`），本版无需成对升级。
- **用极光方块的整合包与玩家需要一步操作**：`client.objectGroups` 没有自动迁移，旧配置文件里的默认组会原样保留。升级后在配置页对「对象组」点一次「恢复默认」，或手动新增成员 `TwilightForest:tile.TFAuroraBrick@*` 并勾选需要的模式，连锁才会恢复成整片。
- 饥饿值消耗的默认值等于原版行为，不配置即无需任何操作；低于 `0.025` 的值无法进一步降低单方块消耗，等效原版基线。
- 已知限制：该配置只覆盖连锁/爆破执行路径，玩家手动挖掉的那一格仍按原版消耗；覆写 `harvestBlock` 且不调用原版实现的方块会少消耗 0.025，自行追加了额外消耗的方块则按追加量多算。
