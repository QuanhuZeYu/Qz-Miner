# Qz-Miner 5.4.1

## 更新

- **修 5.4.0 无法联机（阻断性）**：握手兼容族此前是写死的 `5.3` 常量（`COMPATIBLE_MAJOR` / `COMPATIBLE_MINOR`），制品升到 5.4.0 后越出该族，双方在握手阶段互相拒绝（`Rejecting connection CLIENT: [FMLMod:qz_miner{5.4.0}]`），进世界即被踢。现在族由制品版本 `Tags.VERSION` 的 `major.minor` 推导：**升 minor 即自动切族**，不再需要（也不允许）手改常量。
- **日志不代表策略放行**（同批修正的排查陷阱）：FML 启动日志里的「The mod qz_miner accepts its own version」读的是 `@Mod.acceptableRemoteVersions` 区间；本模组该属性留空，于是退化为「自身版本等于自身」的字符串精确相等，**根本不调用** `@NetworkCheckHandler`。该属性与这条日志都不构成握手策略放行的证据，判定只认策略本身。
- **补自身版本不变量守卫**：测试新增「策略必须接受自身构建版本」三层断言（族判定 / 策略判定 / 真的走 Forge 握手入口），且样本全部由制品版本的族派生、不写死版本号——既有样本恰好全是 5.3.x，正是这一点绕过了该不变量，让 5.4.0 带着缺陷出厂。
- **事件总线监听器异常改走日志系统**：`event/EventBus` 隔离单个监听器异常时用 `e.printStackTrace()` 直写 stderr，无前缀、不受日志级别控制、log4j 无法过滤归档。改为 log4j 直连的 `LOG.error`（该类独立于 `MyMod`、可被其他模组直接复用，故不引 `MyMod.LOG`）。

## 兼容性与升级动作

- **两端都必须升到 5.4.1 或更新**：5.4.0 自身的族判定是 5.3，因此它拒绝一切远端版本，**包括同为 5.4.0 的对端**；5.4.1 端会接受 5.4.0，但 5.4.0 端仍会拒绝 5.4.1。任何一端留在 5.4.0 都联不上机。
- **联机规则**：族 = 本构建版本的 `major.minor`；同族内忽略 patch、prerelease 与 build qualifier 互通，跨族 fail-closed。修复后 5.4.x 之间互通。
- **依赖配对不变**：仍要求 Qz-UILib `>=4.11.0,<5.0.0`（`required-after:qz_uilib@[4.11.0,5.0.0)`）。
- **联机边界不变**：不改 packet / Side、wire / protocol 与 schema 范围。
- **升级动作**：客户端与服务端都替换为 5.4.1；无需手工改配置或迁移数据。
