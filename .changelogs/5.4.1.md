# Qz-Miner 5.4.1

## 更新

- **修 5.4.0 无法联机（阻断性）**：握手兼容族此前是写死的 `5.3` 常量（`COMPATIBLE_MAJOR` / `COMPATIBLE_MINOR`），制品升到 5.4.0 后越出该族，双方在握手阶段互相拒绝（`Rejecting connection CLIENT: [FMLMod:qz_miner{5.4.0}]`），进世界即被踢。
- **联机版本判定改用 FML 原生区间（不再自造）**：兼容范围写成 `@Mod.acceptableRemoteVersions = [X.Y.0-alpha, X.(Y+1).0-alpha)`（`X.Y` = 本构建的 `major.minor`），由构建从制品版本派生为编译期常量，解析与比较交给 FML 的 Maven 版本序实现。自造解析器与 `@NetworkCheckHandler` 一并删除——FML 的 `NetworkModHolder` 里两者互斥：有 handler 时走 `MethodNetworkChecker`，区间对象根本不会被创建，握手与「接受自身版本」自检都会失效。
  - 区间两端写 `-alpha` 的依据：Maven 语义里只有 `alpha` / `beta` / `milestone` / `rc` / `snapshot` 五个已知限定符被判为预发布，且 `alpha` 最小；因此该区间恰好覆盖 X.Y 族（含其预发布与未知限定符），同时把相邻族的最小形态 `X.(Y+1).0-alpha` 挡在上界之外。
  - **语义变化（有意）**：改用 Maven 语义后不再做严格语法校验——`X.Y` 等价于 `X.Y.0` 而被接受，前导零、溢出、Unicode 等形态按该语义解析后参与比较。旧实现在这些形态上 fail-closed；取舍是复用生态已验证的实现，胜过自造并维护一整套边界。
- **启动期自检恢复**：声明区间后，FML 会在启动时用 `acceptVersion` 检查「本 mod 是否接受自身版本」，不接受即报 `appears to reject its own version`——正是 5.4.0 事故缺失的信号。同一条不变量另由 `NetworkVersionRangeTest` 在构建期钉住（含区间边界矩阵，以及「不得声明 `@NetworkCheckHandler`」）。
- **排查陷阱（写进注释与测试）**：FML 启动日志里的「The mod qz_miner accepts its own version」读的是 `acceptableRemoteVersions` 区间，**不经过** `@NetworkCheckHandler`；本模组此前该属性为空，它退化为「自身版本等于自身」的恒真判断，不能作为放行证据。
- **事件总线监听器异常改走日志系统**：`event/EventBus` 隔离单个监听器异常时用 `e.printStackTrace()` 直写 stderr，无前缀、不受日志级别控制、log4j 无法过滤归档。改为 log4j 直连的 `LOG.error`（该类独立于 `MyMod`、可被其他模组直接复用，故不引 `MyMod.LOG`）。

## 兼容性与升级动作

- **两端都必须升到 5.4.1 或更新**：5.4.0 自身的族判定是 5.3，因此它拒绝一切远端版本，**包括同为 5.4.0 的对端**；5.4.1 端会接受 5.4.0，但 5.4.0 端仍会拒绝 5.4.1。任何一端留在 5.4.0 都联不上机。
- **联机规则**：区间 `[X.Y.0-alpha, X.(Y+1).0-alpha)` 内互通（含 patch / prerelease / build qualifier 差异），区间外 fail-closed。修复后 5.4.x 之间互通。
- **依赖配对不变**：仍要求 Qz-UILib `>=4.11.0,<5.0.0`（`required-after:qz_uilib@[4.11.0,5.0.0)`）。
- **联机边界不变**：不改 packet / Side、wire / protocol 与 schema 范围。
- **升级动作**：客户端与服务端都替换为 5.4.1；无需手工改配置或迁移数据。
