# Qz-Miner 5.1.1

## 本次更新

- 自动工具的 physical ledger 统一由服务端主线程本地批量路径持有：服务端冻结 policy、按 live
  candidate 选择工具，并在同一 tick 完成二槽交换或三槽轮转。segment/final restore、每玩家每 tick
  publication gate 与 restore-before-cleanup 共同保证批量接替和收口顺序。
- 新客户端在 round 激活后直接发送 `FREEZE`，由新服务端执行本地批量接替；连接旧服务端时继续使用
  legacy takeover request/RTT fallback。
- 本地成功破坏冻结 origin 后，预览建立 generation-aware origin lease；租约在对应 generation 内锁定
  已触发连锁的预览 origin，并在终态、松键、禁用或 lifecycle 收口时释放，避免准星转向后预览跳到新目标。

## 5.1 兼容合同

- 完整合法的 5.1 patch、prerelease 与 dev 版本继续互通；AutoToolSwap v4 六包及其 framing、
  discriminator、其它 wire/ordinal/code/mask、24-path 配置 schema 与 Qz-UILib 依赖坐标均未改变。
- 旧客户端连接新服务端时，physical intent 以零库存副作用降级；新客户端连接旧服务端时保留 legacy
  RTT fallback。旧/新四象限 mixed packaged JAR 尚未进行真实运行态验证，不将静态兼容结论写成实测通过。
