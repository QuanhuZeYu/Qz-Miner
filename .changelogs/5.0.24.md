# Qz-Miner 5.0.24

## 更新

- 修复 Issue #244 的隧道方向不同步：默认 `LOOK_DIRECTION` 由服务端按玩家视线冻结具体方向，避免规划与执行阶段漂移。
- 新增每玩家配置 `client.tunnelDirectionSource`，可选 `look_direction`（默认）或 `hit_face`；后者取命中表面外法线的 opposite，朝被点击方块内部延伸。
- 客户端预览只使用服务端已接受并 ACK 的方向来源，与服务端规划共用 concrete face；同一原点换方向也会使旧预览协作失效。
- 服务端把 radius、maxBlocks 与方向来源作为每玩家 accepted 原子组发布，连接或玩家生命周期清理后安全回落到 `LOOK_DIRECTION`。

## 兼容性与升级动作

- 兼容边界：保留旧配置帧前缀兼容，新旧端混连只安全降级到 `LOOK_DIRECTION`；非法版本、方向码或帧长度仍整包拒绝。建议联机客户端与服务端安装相同版本的 Qz-Miner，且新客户端不能让旧服务端获得 `HIT_FACE` 能力。
- 依赖配对：必须安装 Qz-UILib `4.6.0` 或更高兼容版本，本版基于 Qz-UILib `4.6.1`。
- 构建基线：支持 GTNH `2.8.4` 与 `2.9.0-beta-2`，默认出包基线 `2.9.0-beta-2`。
- 升级动作：无需手工动作；要用 `hit_face` 需在客户端配置该项。

## 验证边界

- 已验证：修复提交通过全量 `test`、`check`、`build` 与文档门禁。用户在带本地改动的开发包上确认 Issue #244 原症状已修复（该包不等同于本版发布制品）。默认 `LOOK_DIRECTION` 已在真机覆盖 `+X` / `+Z` / `-X` / `+Y` 四个方向，掉落释放与收口正常（其中一次在工具接替后停止并合法收口）；日志本身没有 source / face 显式标记。
- 未验证：`-Y`、`-Z`、`HIT_FACE` 六面、四象限新旧混连与 dedicated server 运行态仍未验证；原症状确认不代表完整方向与兼容矩阵均已通过。
