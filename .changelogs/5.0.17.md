# Qz-Miner 5.0.17

## 更新

- 修复 issue #235：GTNH 2.8.0 dedicated server 启动时，LootGames 扫雷兼容反射解析客户端专属方法签名导致的崩溃。
- LootGames 扫雷兼容不再反射调用含客户端签名风险的方块公开方法，改为基于稳定棋盘布局解析 master、棋盘原点和炸弹坐标。
- 增加可选模组反射成员安全解析，避免兼容探测阶段因第三方类链接失败拖垮 Qz-Miner 初始化。
- 可选模组类探测改为不触发静态初始化，降低服务端初始化阶段的副作用风险。

## 兼容性与升级动作

- 兼容边界：本版主要修复服务端启动兼容性，不改变现有配置项语义。
- 升级动作：GTNH 2.8.0 服务端仍应保留 `lwjgl3ify` 现代 Java 启动链路，不需要通过移除运行时依赖规避问题。
- 已知限制：若开发环境同时启用 ServerUtilities 与 Et Futurum，需关闭 ServerUtilities 的 `enable_player_sleeping_percentage`，以避免两者睡眠百分比 mixin 冲突；这不是本次 Qz-Miner 崩溃的根因。
